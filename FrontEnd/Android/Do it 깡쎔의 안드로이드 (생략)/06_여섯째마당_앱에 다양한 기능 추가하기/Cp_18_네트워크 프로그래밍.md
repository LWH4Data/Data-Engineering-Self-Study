<h1>1. 스마트폰 정보 구하기</h1>
<h2>1-1. 전화 상태 변화 감지하기</h2>
<ul>
  <li>
    스마트폰의 상태를 파악하는 방법은 <strong>PhoneStateListener</strong>를 이용하는 방법과 <strong>TelephonyCallback</strong>을 이용하는 방법 두 가지가 있다.
  </li>
    <ul>
      <li>
        하지만 PhoneStateListener를 이용하는 방법은 안드로이드 12(API 레벨 31)에서 deprecated 되었고 <strong>TelephonyCallback</strong>만이 남아있다.
      </li>
    </ul>
  <li>
    TelephonyCallback을 구현한 객체를 <strong>TelephonyManager</strong>에 등록하면 상태 변화가 발생했을 때 TelephonyCallback 함수가 <strong>자동으로 호출</strong>된다.
  </li>
    <ul>
      <li>
        TelephonyCallback을 TelephonyManager에 등록할 때에는 <strong>registerTelephonyCallback() 함수</strong>를 이용한다.
      </li>
      <li>
        registerTelephonyCallback() 함수에 등록하는 객체는 <strong>TelephonyCallback을 상속</strong> 받아야하며 감지하려는 상태에 따라 <strong>API가 제공하는 인터페이스를 구현</strong>해야 한다.
      </li>
    </ul>
  <li>
    당연히 필요한 퍼미션이 있다면 퍼미션을 등록해야 한다.
  </li>
  <li>
    TelephonyCallback.CallStateListener 이외의 각종 상태 변화를 감지하는 인터페이스들이 준비되어 있으며 대표적으로 다음과 같다.
  </li>
    <ul>
      <li>
        TelephonyCallback.CellLocationListener: 셀(cell) 위치 변화 감지.
      </li>
      <li>
        TelephonyCallback.ServiceStateListener: 서비스 상태 변화 감지.
      </li>
      <li>
        TelephonyCallback.SignalStrenthsListener: 신호 세기 변화 감지.
      </li>
      <li>
        TelephonyCallback.DataActivityListener: 데이터 송수신 상태 변화 감지.
      </li>
      <li>
        TelephonyCallback.DataConnectionStateListener: 데이터 접속 상태 변화 감지.
      </li>
      <li>
        TelephonyCallback.Callback.CallStateListener: 전화 상태 변화 감지.
      </li>
    </ul>
</ul>

```kotlin
// 1. TelephonyMaganer을 이용한 전화 상태 변화 감지.
telephoneManager = getSystemService(Context.TELEPHONY_SERVICE) as TelephonyManager
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
    telephonyManager.registerTelephonyCallback(
        mainExecutor,
        // TelephonyCallback.CallStateListener 인터페이스를 구현.
        object : TelephonyCallback(), TelephonyCallback.CallStateListener {
            override fun onCallStateChnaged(state: Int) {
                when (state) {
                    TelephonyManager.CALL_STATE_IDLE -> {
                        Log.d("kkang", "IDLE")
                    }
                    TelephonyManager.CALL_STATE_OFFHOOK -> {
                        Log.d("kkang", "OFFHOOK")
                    }
                    TelephonyManager.CALL_STATE_RINGING -> {
                        Log.d("kkang", "RINGING")
                    }
                }
            }
        }
    )
}
```

<h2>1-2. 네트워크 제공 국가, 사업자, 전화번호 얻기 - TelephonyManager</h2>
<ul>
  <li>
    TelephonyManager는 네트워크 제공 국가, 사업자, 전화번호 등을 반환하는 함수를 제공한다.
  </li>
    <ul>
      <li>
        <strong>getNetworkCountryIso()</strong>: 네트워크 제공 국가
      </li>
      <li>
        <strong>getNetworkOperatorName()</strong>: 네트워크 제공 사업자
      </li>
    </ul>
  <li>
    사용자 스마트폰의 전화번호를 추출하려면 퍼미션이 필요하다.
  </li>
  <li>
    사용자 스마트폰의 전화번호를 추출하는 방법은 API Level 33 이전까지는 TelephonyManager의 getLine1Number() 함수를 사용하였으나 API Level 33부터는 deprecated 되었다.
  </li>
  <li>
    API Level 33부터는 <strong>SubscriptionManager</strong>의 <strong>getPhoneNumber() 함수</strong>를 사용할 것을 권장한다.
  </li>
    <ul>
      <li>
        SubscriptionManager는 현재 활성화된 <strong>SIM에 대한 정보</strong>와 현재 네트워크가 <strong>로밍 중</strong>인지 등을 확인할 수 있는 방법을 제공하는 시스템 서비스이다.
      </li>
    </ul>
</ul>

```xml
<!-- 1. 사용자 전화번호를 읽는 퍼미션. -->
<uses-permission android:name="android.permission.READ_PHONE_NUMBERS" />
```

```kotlin
// 2. getPhoneNumber() 함수로 전화번호 추출하기.
var phoneNumber: String = "unKnown"

if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {
    val subscriptionManager = getSystemService(Context.TELEPHONY_SUBSCRIPTION_SERVICE) as SubscriptionManager

    for (subscriptionInfo: SubscriptionInfo in subscriptionManager.activeSubscriptionInfoList !!) {
        val activeSubscriptionId: Int = subscriptionInfo.subscriptionId
        phoneNumber = subscriptionManager.getPhoneNumber(activeSubscriptionId)
    }
} else {
    // deprecated
    phoneNumber = telephonyManager.line1Number
}
```

<h3>1-3-1. getActivityNetwork() 함수를 이용하는 방법</h3>
<ul>
  <li>
    스마트폰에서 네트워크가 가능한지, 가능한 경우 어떤 네트워크에 접속돼 있는지 알아볼 때에는 ConnectivityManager의 <strong>getActivityNetwork() 함수</strong>로 <strong>Network 객체</strong>를 얻어서 이용한다.
  </li>
</ul>

```kotlin
// 1. 네트워크 접속 가능 여부.
private fun isNetworkAvailable(): Boolean {
    val connectivityManager = getSystemService(Context.CONNECTIVITY_SERVICE as ConnectivityManager)
    val nw = connectivityManager.activeNetwork ?: return false

    // 네트워크의 정보를 얻음.
    val actNw = connectivityManager.getNetworkCapabilities(nw) ?: return false
    return when {

        // hasTransport() 함수를 통해 와이파이 접속 상태인지 확인.
        actNw.hasTransport(NetworkCapabilities.TRANSPORT_WIFI) -> {
            Log.d("kkang", "wifi available")
            true
        }

        // hasTransport() 함수를 통해 이번에는 이동 통신망 접속 상태인지 확인.
        actNw.hasTransport(NetworkCapabilities.TRANSPORT_CELLULAR) -> {
            Log.d("kkang", "cellular available")
            true
        }
        else -> false
    }
}
```

      </li>

</ul>

```xml
<!-- 1. CHANGE_NETWORK_STATE 퍼미션 설정. -->
<uses-permission android:name="android.permission.CHANGE_NETWORK_STATE" />
```

```kotlin
// 2. 네트워크 타입 지정.
// requestNetwork() 함수는 다음과 같이 지정되어 있어야 한다.
// public void requestNetwork(NetworkRequest request, ConnectivityManager.NetworkCallback networkCallback)
//   - 첫 번째 매개변수: 네트워크 타입을 나타내는 NetworkRequest 객체를 지정.
//     - NetworkReuqest의 addCapability()와 addTransportType() 함수를 이용해 네트워크 타입을 지정할 수도 있다.
val networkReq: NetworkRequest = NetworkRequest.Builder()
    
    // addCapability()에 전달한 상수는 일반적인 데이터 통신을 의미한다.
    .addCapability(NetworkCapabilities.NET_CAPABILITY_INTERNET)

    // 이동 통싡망(TRANSPORT_CELLULAR)
    .addTransportType(NetworkCapabilities.TRANSPORT_CELLULAR)

    // 와이파이(TRANSPORT_WIFI)
    .addTransportType(NetworkCapabilities.TRANSPORT_WIFI)
    .build()
```

```kotlin
// 2. 1번에서 NetworkRequest 객체에 설정한 네트워크 타입을 매개변수로 지정하여 네트워크 사용가능 여부를 반환한다.
conManager.requestNetwork(networkReq, object : ConnectivityManager.NetworkCallback() {

    // onAvailable() 함수가 호출되면 지정한 타입의 네트워크가 사용 가능.
    override fun onAvailable(network: Network) {
        super.onAvailable(network)
        Log.d("kkang", "NetworkCallback...onAvailable....")
    }

    // onUnavailable() 함수가 호출되면 지정한 네트워크 사용 불가능.
    override fun onUnavailable() {
        super.onUnavailable()
        Log.d("kkang", "NetworkCallback...onUnavailable....")
    }
})
```

<h1>2. HTTP 통신하기</h1>
<ul>
  <li>
    앱에서 네트워크 통신을 구현하기 위해서는 매니페스트 파일에 <strong>퍼미션</strong>을 선언해야 한다.
  </li>
  <li>
    안드로이드 앱은 네트워크 통신을 할 때 기본적으로 <strong>HTTPS 보안 프로토콜</strong>을 이용하며 HTTP 프로토콜로 통신을 할 경우 특정 도메인만 허용하도록 선언해 주어야 한다.
  </li>
    <ul>
      <li>
        res/xml 폴더에 XML 파일로 작성한다.
      </li>
      <li>
        domain 태그에 HTTP 통신을 허용할 서버의 <strong>IP</strong>나 <strong>도메인</strong>을 작성한다.
      </li>
    </ul>
  <li>
    작성한 XML 파일을 <strong>매니페스트의 application 태그</strong>에 <strong>networkSecurityConfig 속성</strong>으로 알려주면 해당 도메인에 한해서면 HTTP 통신을 할 수 있다.
  </li>
    <ul>
      <li>
        혹은 매니페스트에서 <strong>usesCleartextTraffic 속성</strong>을 true로 설정하면 <strong>앱 전체</strong>에서 <strong>모든 도메인의 서버</strong>와 <strong>HTTP 통신</strong>을 할 수 있다.
      </li>
    </ul>
</ul>

```xml
<!-- 1. 인터넷 퍼미션 선언. -->
<uses-permission android:name="android.permission.INTERNET" />
```

```xml
<!-- 2. HTTP 통신 허용. -->
<network-security-config>
    <domain-config cleartextTrafficPermitted="true">
        <domain includeSubdomains="true">xxx.xxx.xxx.xxx.</domain>
    </domain-config>
</network-security-config>
```

```xml
<!-- 3. 매니페스트에 HTTP 허용 XML 등록. -->
<application
    (... 생략 ...)
    android:networkSecurityConfig="@xml/network_security_config">
```

```xml
<!-- 4. 모든 HTTP 통신 허용. -->
<application
    (...생략...)
    android:usesCleartextTraffic="true">
```

  </li>
  <li>

    <ul>
      <li>
        RequestQueue: 서버 요청자.
      </li>
        <ul>
          <li>
            서버에 요청을 보내는 역할을 한다.
          </li>
        </ul>
      <li>
        XXXRequest: XXX 타입의 결과를 받는 요청 정보.
      </li>
        <ul>
          <li>
            서버 URL과 결과를 가져오는 콜백 등 다양한 정보를 담아 전송한다.
          </li>
          <li>
            데이터 타입에 따라 StringRequest, ImageRequest, JsonObjectRequest, JsonArrayRequest 등을 이용한다.
          </li>
        </ul>
    </ul>
</ul>

<h3>2-1-1. 문자열 데이터 요청하기 - StringRequest</h3>
<ul>
  <li>
    StringRequest는 서버에 <strong>문자열 데이터를 요청</strong>할 때 사용한다.
  </li>
    <ul>
      <li>
        StringRequest(int method, String url, Response.Listener&ltString&gt listener, Response.ErrorListener errorListener)
      </li>
      <li>
        StringRequest 생성자에는 <strong>HTTP 메서드</strong>, <strong>서버 URL</strong> 그리고 서버로부터 결과를 받을 때 <strong>호출할 콜백</strong>과 서버 연동에 <strong>실패할 때 호출할 콜백</strong>을 지정한다.
      </li>
    </ul>
  <li>
    서버에 요청할 때 데이터를 함께 전달해야 할 경우 <strong>GET 방식</strong>에서는 간단하게 <strong>URL 뒤에 추가</strong>하면 되지만, <strong>POST 방식</strong>에서는 <strong>StringRequest를 상속받은 클래스</strong>를 이용해야 한다.
  </li>
</ul>

```kotlin
// 1. 문자열 요청 정의.
val stringRequest = StringRequest(
    Request.Method.GET,
    url,
    Response.Listener<String> {
        Log.d("kkang", "server data : $it")
    },
    
    // 세 번째 매개변수로 서러로부터 결과를 받는 순간 호출할 콜백이다.
    //   - Response.Listener를 구현한 클래스의 객체이다.
    Response.ErrorListener { error ->
      Log.d("kkang", "error...........$error")}
)
```

```kotlin
// 2. 서버에 요청하기.
// StringRequest에 담은 정보대로 서버에 요청을 보낼 때에는 RequestQueue 객체를 이용한다.

// Volley.newRequestQueue(this)로 RequestQueue 객체를 얻는다.
val queue = Volley.newRequestQueue(this)

// 위에서 얻은 객체를 add() 함수 앞에서 정의한 RequestString 객체를 전달하여 서버에 요청을 보낸다.
queue.add(stringRequest)
```

```kotlin
// 3. POST 방식으로 데이터 전송.
val stringRequest = object : StringRequest(
    
    // POST 방식의 요청.
    Request.Method.POST,
    url,

    // POST 방식이기에 StringRequest를 상속받은 클래스를 이용한다.
    Response.Listener<String> {
        Log.d("kkang", "server data : $it")
    },
    ResponseErrorListener { error -> 
        Log.d("kkang", "error.............$error")
    }){
    
    // getParams() 함수를 재정의하여 작성하면 자동으로 호출된다.
    //   - 함수의 반환값은 MutableMap으로 해당 객체에 데이터를 담아서 반환하면 서버에 요청을 보낼 때 
    //     알아서 자동으로 함께 전송한다.
    override fun getParams(): MutableMap<String, String> {
        return mutableMapOf<String, String>("one" to "hello", "two" to "world")
    }
}
```

<h3>2-1-2. 이미지 데이터 요청하기 - ImageRequest</h3>

```kotlin
// 1. ImageRuquest를 통한 이미지 요청 정의.
val imageRequest = ImageRequest(

    url,

    // decodeConfig: 이미지 형식 지정.
    null,

        Log.d("kkang", "error..................$error")
    })

val queue = Volley.newRequestQueue(this)
queue.add(imageRequest)
```

<h3>2-1-3. 화면 출력용 이미지 데이터 요청하기 - NetworkImageView</h3>
<ul>
  <li>
    ImageRequest가 아닌 <strong>NetworkImageView</strong>를 사용하면 조금 더 편리하게 이미지를 가져올 수 있다.
  </li>
    <ul>
      <li>
        NetworkImageView는 Volley에서 제공하는 이미지 <strong>출력용 뷰</strong>이다.
      </li>
    </ul>
  <li>
    액티비티 화면을 구성하는 레이아웃 XML에 <strong>&ltcom.android.volley.toolbox.NetworkImageView&gt</strong>를 작성하고 해당 객체의 <strong>setImageUrl() 함수</strong>를 호출하면 서버에서 이미지를 가져오는 통신부터 이미지를 NetworkImageView에 출력하는 것까지 <strong>자동으로 수행</strong>된다.
  </li>
    <ul>
      <li>
        setImageUrl(String url, ImageLoader imageLoader)
      </li>
    </ul>
  <li>
    setImageUrl() 함수만으로 서버에 요청을 보낼 수 있다.
  </li>
    <ul>
      <li>
        RequestQueue의 add() 함수를 호출하지 않아도 서버와 자동으로 연결된다.
      </li>
      <li>
        대신 함수의 두 번째 매개변수에 ImageLoader를 상속받은 하위 클래스의 객체를 지정해야 한다.
      </li>
    </ul>
  <li>
    getBitmap() 함수가 null을 반환해서 서버로부터 이미지를 가져오면 <strong>putBitmap() 함수</strong>가 자동으로 호출되어 서버 이미지를 putBitmap() <strong>두 번째 매개변수</strong>로 전달한다.
  </li>
</ul>

```xml

<com.android.volley.toolbox.NetworkImageView
    android:id="@+id/networkImageView"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content" />
```

```kotlin
// 2. setImageUrl() 함수로 요청하기.
val queue = Volley.newRequestQueue(this)
val imgMap = HashMap<String, Bitmap>()

// ImageCache는 이미지를 저장하는 메모리를 할당하는 역할을 한다.
imageLoader = ImageLoader(queue, object : ImageLoader.ImageCache {
    override fun getBitmap(url: String): Bitmap? {
        return imgMap[url]
    }

    override fun putBitmap(url: String, bitmap: Bitmap) {
        imgMap[url] = bitmap
    }
})

// setImageUrl의 두 번째 매개변수에 상단에서 생성한 imageLoader 객체를 지정한다.
// → 서버 이미지를 가져오기 전 ImageLoader의 getBitmap() 함수가 자동으로 호출된다.
// → 반환값이 null이면 서버로부터 이미지를 요청한다 반면 Bitmap 객체를 반환하면 요청을 보내지 않고
//   Bitmap 객체를 그대로 NetworkImageView에 출력한다.
binding.networkImageView.setImageUrl(url, imageLoader)
```

<h3>2-1-4. JSON 데이터 요청하기 - JsonObjectRequest</h3>
<ul>
  <li>
    서버에 <strong>JSON 데이터</strong>를 요청할 때에는 <strong>JsonObejctRequest</strong>를 이용한다.
  </li>
    <ul>
      <li>
        자동으로 JSON 데이터를 파싱한 JSONObejct 객체가 콜백 함수에 전달된다.
      </li>
      <li>
        JsonObjectRequest(int method, String url, JSONObject jsonRequest, Response.Listener&ltJSONObject&gt listener, Response.ErrorListener errorListener)
      </li>
    </ul>
  <li>
    서버에 요청할 때 전송해야 하는 데이터를 JsonObjectRequest() 함수의 <strong>세 번째 매개변수</strong>에 JSONObejct로 지정할 수 있으며 null인 경우 <strong>전송할 데이터가 없음</strong>을 의미한다.
  </li>
</ul>

```kotlin
// 1. JSON 데이터 요청하기.
val jsonRequest = JsonObjectRequest(
    Request.Method.GET,
    url,
    null,

    // 네 번째 매개변수는 결과를 받는 콜백으로 서버로부터 넘어오는 JSON을 파싱한 JSONObject 객체가 전달된다.
    //   - 해당 객체의 getter 함수를 이용해 가져올 데이터의 키값을 명시한다.
    Response.Listener<JSONObejct> { response ->
        
        // 가져올 데이터의 키값(tile, date)을 명시.
        val title = response.getString("title")
        val date = response.getString("date")
        Log.d("kkang", "$title, $date")
    },
    Response.ErrorListener { error -> Log.d("kkang", "error....$error")
    })
val queue = Volley.newRequestQueue(this)
queue.add(jsonRequest)
```

<h2>2-2. Retrofit 라이브러리</h2>
<ul>
  <li>
    Retrofit은 스퀘어에서 만든 HTTP 통신을 간편하게 해주는 라이브러리로 1 버전과 2 버전이 있으나 2 버전이 2015년도에 나왔으므로 현재는 모두 2 버전이라 보면 된다.
  </li>
  <li>
    Retrofit은 <strong>네트워크 통신 정보</strong>만 주면 그대로 <strong>네트워크 프로그래밍</strong>을 대신 구현해준다.
  </li>
  <li>
    Retrofit을 활용하는 과정은 다음과 같다.
  </li>
    <ul>
      <li>
        통신용 함수를 선언한 인터페이스를 작성한다(kotlin).
        <br>→ Retrofit에 인터페이스를 전달한다.
        <br>→ Retrofit이 통신용 서비스 객체를 반환한다. (자동으로 인터페이스 구현).
        <br>→ 서비스의 통신용 함수를 호출한 후 Call 객체를 반환한다.
        <br>→ Call 객체의 enqueue() 함수를 호출하여 네트워크 통신을 수행한다.
      </li>
    </ul>
</ul>

<h3>2-2-2. 모델 클래스 선언</h3>
<ul>
  <li>
    모델 클래스란 <strong>서버와 주고받는 데이터</strong>를 표현하는 클래스이다. 흔히 <strong>VO(value-object) 클래스</strong>라고도 하며 JSON, XML 데이터를 <strong>파싱</strong>해 <strong>모델 클래스 객체</strong>에 담는 것을 자동화해 준다.
  </li>
  <li>
    원래는 JSON 데이터를 직접 코드에서 파싱해야 하지만 데이터를 담을 <strong>모델 클래스</strong>를 선언하고 <strong>클래스 정보</strong>만 알려 주면 된다.
  </li>
    <ul>
      <li>
        전달 받은 클래스 정보를 기반으로 모델 클래스의 객체를 알아서 생성하고 해당 객체에 데이터를 담아준다.
      </li>
    </ul>
  <li>
    모델 클래스는 상위 타입에 제약이 없어 어떤 클래스를 상속받거나 인터페이스를 구현할 필요 없이 순전히 <strong>개발자가 작성하는 클래스</strong>이다.
  </li>
  <li>
    모델 클래스의 프로퍼티에 데이터가 자동으로 저장되는 기본 규칙은 데이터의 <strong>키</strong>와 <strong>프로퍼티 이름</strong>을 <strong>매칭</strong>하는 것이다.
  </li>
    <ul>
      <li>
        키와 프로퍼티 이름이 <strong>다를 때</strong>에는 <strong>@SerializedName</strong>이라는 애너테이션으로 명시해준다.
      </li>
      <li>
        서버의 데이터와 <strong>상관없는 프로퍼티</strong>를 선언해도 된다. 즉, 서버에서부터 받는 JSON에 해당 데이터가 없어도 된다.
      </li>
      <li>
        서버의 데이터가 복잡한 경우 여러 모델 클래스로 <strong>분리한 후 조합</strong>해서 사용할 수도 있다.
      </li>
    </ul>
</ul>

```kotlin

data class UserModel(
    val id: String,

    // first_name이라는 키의 데이터가 firstName 프로퍼티에 저장된다.
    @SerializedName("first_name")
    var firstName: String,
    // @SerializedName("last_name")
    var lastName: String,
    var avatar: String,
    var avatarBitmap: Bitmap
)
```

```kotlin
// 2. 1 번과 다른 클래스를 생성하여 하나의 데이터를 두 개의 모델 클래스로 분할하여 저장한다.
data class UserListModel(
    var page: String,
```

<h2>2-3. Retrofit 애너테이션</h2>
<ul>
  <li>

<h3>2-3-1. @GET, @POST, @PUT, @DELETE, @HEAD</h3>

  <li>

<h3>2-3-3. @Query</h3>

  <li>

```kotlin
// 1. 질의 애너테이션 예.
// 인터페이스에 선언한 함수.
@GET("group/users")
fun test3(
  
    // sort를 key로 매개변숫값을 값으로 해서 서버에 전달한다.
    @Query("sort") arg1: String,

    // name을 key로 매개변숫값을 값으로 해서 서버에 전달한다.
    @Query("name") arg2: String
): Call<UserModel>

// Call 객체를 얻는 구문.
val call: Call<UserModel> = networkService.test3("age", "kkang")

// 최종 서버 요청 URL
https://reqres.in/group/users?.sort=age&name=kkang
```

<h3>2-3-4. @QueryMap</h3>
<ul>
  <li>
    서버에 전송할 데이터가 많아 여러 개의 매개변수를 선언해야 하는 경우 @QueryMap을 이용해 서버에 전송할 데이터를 <strong>Map 타입의 매개변수</strong>로 받으면 된다.
  </li>
</ul>

```kotlin
// 1. 질의 맵 애너테이션 예.
// 인터페이스에 선언한 함수.
@GET("group/users")
fun test4(
    @QueryMap options: Map<String, String>,
    @Query("name") name: String
): Call<UserModel>

// Call 객체를 얻는 구문.
val call: Call<UserModel> = networkService.test4(
    mapOf<String, String>("one" to "hello", "two" to "world"),
    "kkang"
)

// 최종 서버 요청 URL
https://reqres.in/group/users?name=kkang
```

<h3>2-3-5. @Body</h3>
<ul>
  <li>
    서버에 전송할 데이터를 <strong>모델 객체</strong>로 지정하고 싶은 경우 <strong>@Body 애너테이션</strong>을 사용한다.
  </li>
    <ul>
      <li>
        @Body로 선언한 매개변수는 <strong>모델 객체 타입</strong>이다.
      </li>
      <li>
        객체의 <strong>프로퍼티명</strong>을 <strong>키</strong>로, 프로퍼티의 <strong>데이터</strong>를 <strong>값</strong>으로 해서 JSON 문자열을 만들어 서버에 전송한다.
      </li>
      <li>
        JSON 문자열은 <strong>데이터 스트림</strong>을 전송하기 때문에 @Body는 @GET에서 사용할 수 없으며 <strong>@POST</strong>와 사용해야 한다.
      </li>
    </ul>
  <li>
    @Body로 지정한 모델의 데이터는 객체의 내용을 <strong>JSON 문자열</strong>로 만들어 데이터 스트림으로 서버에 전송한다.
  </li>
</ul>

```kotlin
// 1. 모델 객체 애너테이션 예.
@POST("group/users")
fun text5(
    @Body user: UserModel,
    @Query("name") name: String
): Call<UserModel>

// Call 객체를 얻는 구문.
val call: Call<UserModel> = networkService.test5(
    UserModel(id="1", firstName = "gildong", "lastName = "hong", avatar = "someurl"),
    "kkang"
)

// 최종 서버 요청 URL
https://reqres.in/group/users?name=kkang

// 서버에 스트림으로 전송되는 데이터.
{"id":"1", "first_name":"gildong", "last_name":"hong", "avatar":"someurl"}
```

<h3>2-3-6. @FormUrlEncoded와 @Field</h3>
<ul>
  <li>
    @FormUrlEncoded 애너테이션은 데이터를 <strong>URL 인코딩 형태</strong>로 만들어 전송할 때 사용한다.
  </li>
    <ul>
      <li>
        @FormUrlEncoded는 서버 전송 데이터를 <strong>'키=값' 형태의 URL</strong>로 인코딩하여 전송한다.
      </li>
      <li>
        <strong>@Field 애너테이션</strong>이 추가된 데이터를 인코딩해서 전송하며 @FormUrlEncoded 애너테이션을 사용할 때만 적용할 수 있다.
      </li>
    </ul>
  <li>
    @FormUrlEncoded 애너테이션은 <strong>@POST 방식</strong>에서만 사용할 수 있다.
  </li>
  <li>
    @Field 애너테이션은 모델 객체에는 사용할 수 없기 때문에 데이터를 여러 건을 한꺼번에 지정하고 싶은 경우 <strong>배열</strong>이나 <strong>List 객체</strong>를 이용해야 한다.
  </li>
    <ul>
      <li>
        배열이나 List를 이용하면 데이터 여러 건을 <strong>같은 키</strong>로 서버에 전달할 수 있다.
      </li>
    </ul>
</ul>

```kotlin
// 1. URL 인코딩 애너테이션 예.
// 인터페이스에 선언한 함수.
@FormUrlEncoded
@POST("user/edit")
fun test6(
    @Field("first_name") first:String?,
    @Filed("last_name") last: String?,
    @Query("name") name: String?
): Call<UserModel>

// Call 객체를 얻는 구문.
val call: Call<UserModel> = networkService.test6(
    "gildong 길동",
    "hong 홍",
    "kkang"
)

// 최종 서버 요청 URL
https://reqres.in/user/edit?name=kkang

// 서버에 스트림으로 전송되는 데이터 (인코딩된 데이터가 key-value 형식으로 전달된다).
first_name=gildong%20%EA%B8%B8%EB%8F%99&last_name=hong%20%ED%99%8D
```

```kotlin
// 2. 리스트에 필드 애너테이션 사용 예.
// 인터페이스에 선언한 함수.
@FormUrlEncoded
@POST("tasks")
fun test7(@Field("title") titles: List<String>): Call<UserModel>

// Call 객체를 얻는 구문.
val list: MutableList<String> = ArrayList()
list.add("홍길동")
list.add("류현진")
val call = networkService.test7(list)

// 최종 서버 요청 URL
https://reqres.in/tasks

// 서버에 스트림으로 전송되는 데이터.
title=%ED%99%8D%EA%B8%B8%EB%8F%99%title=%EB%A5%98%ED%98%84%EC%A7%84
```

<h3>2-3-7. @Header</h3>

</ul>

<h1>3. 이미지 처리하기 - Glide 라이브러리</h1>
<ul>
  <li>
    서버에서 <strong>이미지를 내려받을 때</strong> Glide를 이용하면 네트워크 부분을 Volley나 Retrofit보다 더 쉽고 빠르게 개발할 수 있다.
  </li>
  <li>
    Glide는 Bump라는 앱에서 내부적으로 이용하다가 구글이 인수하여 공개한 라이브러리이며 모든 종류의 이미지를 가능한 한 빠르게 가져와 이용할 수 있게 한다.
  </li>
  <li>
    이미지 크기를 조절하거나 로딩 이미지, 오류 이미지 표시 등을 쉽게 구현할 수 있다.
  </li>
  <li>
    Glide를 이용하려면 빌드 그래들의 dependencies에 다음처럼 등록한다.
  </li>
    <ul>
      <li>
        implementation("com.github.bumptech.glide:glide:4.16.0")
      </li>
    </ul>
</ul>

<br>

<h2>3-1. 이미지를 가져와 출력하기</h2>
<ul>
  <li>
    앱에서 이용하는 이미지는 리소스, 파일, 서버 이미지로 Glide로 쉽게 가져와 이미지 뷰에 출력할 수 있다.
  </li>
  <li>
    Glide는 <strong>애니메이션 효과</strong>를 포함한 GIF 이미지를 출력할 수 있다.
  </li>
</ul>

```kotlin
// 1. 리소스 이미지 출력.

    .load(R.drawable.seoul)

    .into(binding.resultView)
```

```kotlin
// 2. 파일 이미지 출력.
val requestLauncher = registerForActivityResult(
```

<h2>3-2. 크기 조절</h2>
<ul>
  <li>
    Glide를 이용하면 코드에서 이미지 크기를 줄이지 않아도 <strong>이미지 뷰의 크기에 맞게</strong> 자동으로 크기를 줄여서 불러오기 때문에 OOM(out of memory) 문제를 크게 신경쓰지 않아도 된다.
  </li>
    <ul>
      <li>
        만약 특정한 크기로 이미지를 줄이고 싶다면 <strong>override() 함수</strong>를 사용하면 된다.
      </li>
    </ul>
</ul>

```kotlin
// 1. 크기 조절.
Glide.with(this)
    .load(R.drawable.seoul)

    // override로 크기 조절하기.
    .override(200, 200)
    .into(binding.resultView)
```

<h2>3-3. 로딩, 오류 이미지 출력</h2>
<ul>
  <li>
    파일이나 서버에 있는 이미지를 불러오는 데 시간이 걸리면 <strong>로딩 상태를 표현하는 이미지</strong>를, 서버 접속이 원활하지 않아 이미지를 불러올 수 없는 경우 <strong>오류 이미지</strong>를 출력하는데 이때에는 <strong>placeholder()</strong>, <strong>error()</strong> 함수를 사용하여 해당하는 상황에 표시할 이미지를 지정한다.
  </li>
</ul>

```kotlin
// 1. 로딩, 오류 이미지 출력.
Glide.with(this)
    .load(url)
    .override(200, 200)

    // placeholder() 사용.
    //   - placeholder() 함수에 지정한 이미지를 먼저 출력한다.
    //   - 성공적으로 이미지를 불러오면 load() 함수에 지정한 이미지를 출력한다.
    .placegolder(R.drawable.loading)
    
    // error() 함수 사용.
    //   - 이미지를 불러오는데 실패하면 error() 함수에 지정한 이미지를 출력한다.
    .error(R.drawable.error)
    .into(binding.resultView)
```
