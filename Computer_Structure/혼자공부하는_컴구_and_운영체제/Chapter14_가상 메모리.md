<h1>1. 연속 메모리 할당</h1>
<ul>
  <li>
    프로세스에 연속적인 메모리 공간을 할당하는 방식을 <strong>연속 메모리 할당 방식</strong>이라 한다.
  </li>
</ul>

<br>

<h2>1-1. 스와핑</h2>
<ul>
  <li>
    메모리에 적재된 프로세스들 중에 <strong>대기 상태</strong>가 되거나 <strong>오랫동안 사용되지 않은 프로세스</strong>가 있을 수 있다. 이런 프로세스들을 보조기억장치 일부 영역으로 <strong>쫓아내어 생긴 메모리</strong>상의 빈 공간에 또 <strong>다른 프로세스를 적재</strong>하여 실행하는 방식을 <strong>스와핑(swapping)</strong>이라 한다.
  </li>
    <ul>
      <li>
        프로세스들이 쫓겨나는 보조기억장치의 일부 영역을 <strong>스왑 영역(swap space)</strong>이라 한다.
      </li>
      <li>
        현재 실행되지 않는 프로세스가 메모리에서 스왑 영역으로 옮겨지는 것을 <strong>스왑 아웃(swap-out)</strong>이라 한다.
      </li>
      <li>
        스왑 영역에 있던 프로세스가 다시 메모리로 옮겨오는 것을 <strong>스왑 인(swap-in)</strong>이라 한다.
      </li>
        <ul>
          <li>
            스왑 아웃되었던 프로세스가 다시 스왑 인될 때는 스왑 아웃되기 전의 물리 주소와는 <strong>다른 주소</strong>에 적재될 수 있다.
          </li>
        </ul>
    </ul>
</ul>

<h4>스왑 영역 확인하기</h4>
<ul>
  <li>
    유닉스, 리눅스, macOS에서는 free, top 명령어 등을 통해 스왑 영역의 크기를 확인할 수 있다.
  <li>
    스왑 영역의 크기와 사용 여부는 사용자가 임의로 설정할 수 있다.
  </li>
</ul>

<br>

<h2>1-2. 메모리 할당</h2>
<ul>
  <li>
    비어 있는 메모리 공간에 프로세스를 연속적으로 할당하는 방식에는 <strong>최초 적합</strong>, <strong>최적 적합</strong>, <strong>최악 적합</strong> 세 가지 방식이 있다.
  </li>
</ul>

<h3>1-2-1. 최초 적합</h3>
<ul>
  <li>
    <strong>최초 적합(first fit)</strong>은 운영체제가 메모리 내의 빈 공간을 <strong>순서대로 검색</strong>하다가 <strong>적재할 수 있는 공간을 발견</strong>하면 해당 공간에 프로세스를 배치하는 방식이다.
  </li>
  <li>
    최초 적합은 프로세스가 적재될 수 있는 공간을 발견하는 즉시 메모리를 할당하는 방식으로 <strong>검색을 최소화</strong>할 수 있고 결과적으로 <strong>빠른 할당</strong>이 가능하다.
  </li>
</ul>

<h3>1-2-2. 최적 적합</h3>
<ul>
  <li>
    <strong>최적 적합(best fit)</strong>은 운영체제가 빈 공간을 <strong>모두 검색</strong>해 본 후, 프로세스가 적재될 수 있는 공간 중 <strong>가장 작은 공간</strong>에 프로세스를 배치하는 방식이다.
  </li>
</ul>

<h3>1-2-3. 최악 적합</h3>
<ul>
  <li>
    <strong>최악 적합(worst fit)</strong>은 운영체제가 빈 공간을 <strong>모두 검색</strong>해 본 후, 프로세스가 적재될 수 있는 공간 중 <strong>가장 큰 공간</strong>에 프로세스를 배치하는 방식이다.
  </li>
</ul>

<br>

<h2>1-3. 외부 단편화</h2>
<ul>
  <li>
    프로세스를 메모리에 연속적으로 배치하는 연속 메모리 할당은 <strong>외부 단편화(external fragmentation)</strong> 문제를 내포하고 있어 효율적인 방법은 아니다.
  </li>
    <ul>
      <li>
        외부 단편화란 순차적으로 적제한 프로세스들이 실행되고 종료되기를 반복하면 결국 <strong>불연속적인 빈 공간</strong>들이 만들어지는 것을 의미한다.
      </li>
    </ul>
  <li>
    외부 단편화를 해결할 수 있는 대표적인 방안으로 메모리를 <strong>압축(compaction)</strong>하는 방법이 있다.
  </li>
    <ul>
      <li>
        압축은 여기저기 <strong>흩어져 있는 빈 공간들을 하나로 모으는 방식</strong>으로 메모리 내에 저장된 프로세스를 적당히 재배치시켜 여기저기 <strong>흩어져 있는 작은 빈 공간들을 하나의 큰 공간</strong>으로 만든다.
      </li>
      <li>
        그러나 압축 방법은 압축하는 과정에서 <strong>시스템은 하던 일을 중지</strong>하고, 메모리에 있는 내용을 <strong>옮기는 작업</strong>은 많은 오버헤드를 야기하며, 어떤 프로세스를 <strong>어떻게 움직여야 오버헤드를 최소화</strong>할 수 있는지 명확한 방법을 결정하기 어렵다는 단점이 있다.
      </li>
    </ul>
  <li>
    압축 이외에 외부 단편화를 없앨 수 있는 해결 방안으로는 <strong>가상 메모리 기법</strong>, 그 중에서도 <strong>페이징 기법</strong>이 있으며 오늘날까지도 사용되는 방법이다.
  </li>
</ul>

<br><br>

<h1>2. 페이징을 통한 가상 메모리 관리</h1>
<ul>
  <li>
    프로세스를 메모리에 연속적으로 할당하는 방식은 앞서 다루었던 외부 단편화 외에도 <strong>물리 메모리보다 큰 프로세스를 실행할 수 없다</strong>는 점이 있다.
  </li>
  <li>
    <strong>가상 메모리(virtual memory)</strong>는 실행하고자 하는 프로그램을 <strong>일부만 메모리에 적재</strong>하여 실제 물리 메모리 크기보다 더 큰 프로세스를 실행할 수 있게 하는 기술이다.
  </li>
    <ul>
      <li>
        가상 메모리 관리 기법에는 크게 <strong>페이징</strong>과 <strong>세그멘테이션</strong>이 있지만, 도서에서는 페이징 기법을 다룬다.
      </li>
    </ul>
</ul>

<br>

<h2>2-1. 페이징이란</h2>
<ul>
  <li>
    <strong>페이징(paging)</strong>은 프로세스의 논리 주소 공간을 <strong>페이지(page)</strong>라는 일정한 단위로 자르고, 메모리 물리 주소 공간을 <strong>프레임(frame)</strong>이라는 페이지와 동일한 크기의 일정한 단위로 <strong>자른 뒤 페이지를 프레임에 할당</strong>하는 가상 메모리 관리 기법이다.
  </li>
  <li>
    페이징에서는 페이지 단위로 스완 아웃, 스왑 인 되며 페이징 시스템에서는 이를 <strong>페이지 아웃(page out)</strong>과 <strong>페이지 인(page in)</strong>이라고 부른다.
  </li>
  <li>
    페이징을 통해 한 프로세스를 실행하기 위해 프로세스 <strong>전체가 메모리에 적재될 필요가 없으며</strong> 프로세스를 이루는 페이지 중 <strong>실행에 필요한 일부</strong> 페이지만 메모리에 적재하고, 당장 실행에 필요하지 않은 페이지들은 <strong>보조기억장치</strong>에 남겨둘 수 있다.
  </li>
</ul>

<br>

<h2>2-2. 페이지 테이블</h2>
<ul>
  <li>
    메모리에 불연속적으로 프로세스가 배치되어 있으면 CPU가 이를 실행할 수가 없다. 따라서 <strong>물리 주소에 불연속적</strong>으로 배체되더라도 <strong>논리 주소에는 연속적</strong>으로 배치되도록 페이지 테이블(page table)을 이용한다.
  </li>
  <li>
    페이지 테이블은 <strong>페이지 번호</strong>와 <strong>프레임 번호</strong>를 짝지어 주는 일종의 이정표이다.
  </li>
    <ul>
      <li>
        CPU는 페이지 번호만 보고 해당 페이지가 적재된 프레임을 찾을 수 있다.
      </li>
    </ul>
  <li>
    프로세스마다 <strong>각자의 프로세스 테이블</strong>을 가지고 있고 각 프로세스의 페이지 테이블들은 <strong>메모리에 적재</strong>되어 있다.
  </li>
    <ul>
      <li>
        CPU 내의 <strong>페이지 테이블 베이스 레지스터(PTBR; Page Table Base Register)</strong>는 각 프로세스의 <strong>페이지 테이블이 적재된 주소</strong>를 가지키고 있다.
      </li>
      <li>
        각 프로세스들의 페이지 테이블 정보들은 <strong>각 프로세스의 PCB</strong>에 기록되며 프로세스의 <strong>문백 교환</strong>이 일어날 때 다른 레지스터와 마찬가지로 함께 변경된다.
      </li>
    </ul>
  <li>
    이렇게 페이지 테이블을 메모리에 두면 생기는 문제는 <strong>메모리 접근 시간이 두 배</strong>로 늘어난다는 점이다.
  </li>
    <ul>
      <li>
        메모리에 있는 페이지 테이블을 확인 → 확인한 프레임에 접근
      </li>
    </ul>
  <li>
    메모리 접근 시간을 단축하기 위해서 CPU 곁에(일반적으로는 MMU 내에) <strong>TLB(Translation Lookaside Buffer)</strong>라는 <strong>페이지 테이블의 캐시 메모리</strong>를 둔다.
  </li>
    <ul>
      <li>
        보편적으로 사용하는 CPU 곁에는 TLB가 있다.
      </li>
      <li>
        TLB는 페이지 테이블의 캐시이기 때문에 페이지 테이블의 일부 내용을 저장한다.
      </li>
    </ul>
  <li>
    CPU가 발생한 논리 주소에 대한 페이지 번호가 TLB에 있는 경우 이를 <strong>TLB 히트(TLB hit)</strong>라고 한다.
  </li>
    <ul>
      <li>
        페이지가 적재된 프레임을 알기 위해 메모리에 접근할 필요가 없다.
      </li>
    </ul>
  <li>
    CPU가 발생한 논리 주소에 대한 페이지 번호가 TLB에 없는 경우 <strong>TLB 미스(TLB miss)</strong>라 하며 이 경우는 <strong>메모리 내의 페이지 테이블에 접근</strong>을 해야한다.
  </li>
</ul>

<h4>내부 단편화</h4>
<ul>
  <li>
    페이징은 외부 단편화 문제를 해결할 수 있지만, <strong>내부 단편화(internal fragmentation)</strong>라는 문제를 야기할 수 있다.
  </li>
  <li>
    프로세스를 일정한 단위로 나눈다 해도 실제로 프로세스의 크기가 <strong>나누어 떨어지는 것이 아니기 때문에</strong> 낭비되는 메모리가 생길 수 있으며 이를 내부 단편화라 한다.
  </li>
  <li>
    내부 단편화는 하나의 페이지 크기보다 작은 크기로 발생한다.
  </li>
    <ul>
      <li>
        하나의 페이지 크기가 작다면 발생하는 내부 단편화의 크기는 작아질 것으로 기대할 수 있다.
      </li>
        <ul>
          <li>
            하지만 너무 페이지 크기가 작다면 페이지 테이블의 크기가 커지기 때문에 페이지 테이블이 차지하는 공간이 낭비된다. 따라서 적당한 크기의 페이지를 설정하는 것이 중요하다.
          </li>
        </ul>
    </ul>
  <li>
    리눅스를 포함한 일부 운영체제는 <strong>기본적으로 설정된 페이지 크기보다 더 큰 크기의 페리지</strong>도 일부 허용하며 메모리에 유지하는 경우도 있다. 이 경우 설저된 페이지보다 큰 페이지를 <strong>대형 페이지(huge page)</strong>라고 한다.
  </li>
</ul>

<br>

<h2>2-3. 페이징에서의 주소 변환(p410)</h2>
<ul>
  <li>
    하나의 페이지 혹은 프레임은 해당하는 연속적인 메모리 주소(여러 주소)를 포괄하고 있다. 따라서 특정 주소에 접근하기 위해서는 아래의 두 가지 정보가 필요하다.
  </li>
    <ol>
      <li>
        <strong>어떤</strong> 페이지 혹은 프레임에 접근하고 싶은지
      </li>
      <li>
        접근하려는 주소가 그 페이지 혹은 프레임으로부터 <strong>얼마나 떨어져</strong> 있는지
      </li>
    </ol>
  <li>
    결국 어떤 위치 그리고 얼마나 떨어져 있는지를 파악하기 위해 페이징 시스템에서는 모든 논리 주소가 기본적으로 <strong>페이지 번호(page number)</strong>와 <strong>변위(offset)</strong>로 이루어져 있다.
  </li>
    <ul>
      <li>
        예를 들어 CPU가 32비트 주소를 보냈다면 이중 N비트는 페이지 번호, 32-N비트는 변위로 설정할 수 있다.
      </li>
      <li>
        페이지 번호는 접근하고자 하는 페이지 번호이며 해당 페이지 번호를 찾으면 페이지가 <strong>어떤 프레임에 할당</strong> 되었는지 알 수 있다.
      </li>
      <li>
        변위는 접근하려는 주소가 프레임의 시작 번지로부터 <strong>얼만큼 떨어져 있는지</strong>를 알기 위한 정보이다.
      </li>
      <li>
        요약하면 논리 주소 &lt페이지 번호, 변위&gt는 페이지 테이블을 통해 물리 주소 &lt프레임 번호, 변위&gt로 변환된다.
      </li>
    </ul>
</ul>
