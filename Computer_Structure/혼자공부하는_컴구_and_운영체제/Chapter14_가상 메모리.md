<h1>1. 연속 메모리 할당</h1>
<ul>
  <li>
    프로세스에 연속적인 메모리 공간을 할당하는 방식을 <strong>연속 메모리 할당 방식</strong>이라 한다.
  </li>
</ul>

<br>

<h2>1-1. 스와핑</h2>
<ul>
  <li>
    메모리에 적재된 프로세스들 중에 <strong>대기 상태</strong>가 되거나 <strong>오랫동안 사용되지 않은 프로세스</strong>가 있을 수 있다. 이런 프로세스들을 보조기억장치 일부 영역으로 <strong>쫓아내어 생긴 메모리</strong>상의 빈 공간에 또 <strong>다른 프로세스를 적재</strong>하여 실행하는 방식을 <strong>스와핑(swapping)</strong>이라 한다.
  </li>
    <ul>
      <li>
        프로세스들이 쫓겨나는 보조기억장치의 일부 영역을 <strong>스왑 영역(swap space)</strong>이라 한다.
      </li>
      <li>
        현재 실행되지 않는 프로세스가 메모리에서 스왑 영역으로 옮겨지는 것을 <strong>스왑 아웃(swap-out)</strong>이라 한다.
      </li>
      <li>
        스왑 영역에 있던 프로세스가 다시 메모리로 옮겨오는 것을 <strong>스왑 인(swap-in)</strong>이라 한다.
      </li>
        <ul>
          <li>
            스왑 아웃되었던 프로세스가 다시 스왑 인될 때는 스왑 아웃되기 전의 물리 주소와는 <strong>다른 주소</strong>에 적재될 수 있다.
          </li>
        </ul>
    </ul>
</ul>

<h4>스왑 영역 확인하기</h4>
<ul>
  <li>
    유닉스, 리눅스, macOS에서는 free, top 명령어 등을 통해 스왑 영역의 크기를 확인할 수 있다.
  <li>
    스왑 영역의 크기와 사용 여부는 사용자가 임의로 설정할 수 있다.
  </li>
</ul>

<br>

<h2>1-2. 메모리 할당</h2>
<ul>
  <li>
    비어 있는 메모리 공간에 프로세스를 연속적으로 할당하는 방식에는 <strong>최초 적합</strong>, <strong>최적 적합</strong>, <strong>최악 적합</strong> 세 가지 방식이 있다.
  </li>
</ul>

<h3>1-2-1. 최초 적합</h3>
<ul>
  <li>
    <strong>최초 적합(first fit)</strong>은 운영체제가 메모리 내의 빈 공간을 <strong>순서대로 검색</strong>하다가 <strong>적재할 수 있는 공간을 발견</strong>하면 해당 공간에 프로세스를 배치하는 방식이다.
  </li>
  <li>
    최초 적합은 프로세스가 적재될 수 있는 공간을 발견하는 즉시 메모리를 할당하는 방식으로 <strong>검색을 최소화</strong>할 수 있고 결과적으로 <strong>빠른 할당</strong>이 가능하다.
  </li>
</ul>

<h3>1-2-2. 최적 적합</h3>
<ul>
  <li>
    <strong>최적 적합(best fit)</strong>은 운영체제가 빈 공간을 <strong>모두 검색</strong>해 본 후, 프로세스가 적재될 수 있는 공간 중 <strong>가장 작은 공간</strong>에 프로세스를 배치하는 방식이다.
  </li>
</ul>

<h3>1-2-3. 최악 적합</h3>
<ul>
  <li>
    <strong>최악 적합(worst fit)</strong>은 운영체제가 빈 공간을 <strong>모두 검색</strong>해 본 후, 프로세스가 적재될 수 있는 공간 중 <strong>가장 큰 공간</strong>에 프로세스를 배치하는 방식이다.
  </li>
</ul>

<br>

<h2>1-3. 외부 단편화</h2>
<ul>
  <li>
    프로세스를 메모리에 연속적으로 배치하는 연속 메모리 할당은 <strong>외부 단편화(external fragmentation)</strong> 문제를 내포하고 있어 효율적인 방법은 아니다.
  </li>
    <ul>
      <li>
        외부 단편화란 순차적으로 적제한 프로세스들이 실행되고 종료되기를 반복하면 결국 <strong>불연속적인 빈 공간</strong>들이 만들어지는 것을 의미한다.
      </li>
    </ul>
  <li>
    외부 단편화를 해결할 수 있는 대표적인 방안으로 메모리를 <strong>압축(compaction)</strong>하는 방법이 있다.
  </li>
    <ul>
      <li>
        압축은 여기저기 <strong>흩어져 있는 빈 공간들을 하나로 모으는 방식</strong>으로 메모리 내에 저장된 프로세스를 적당히 재배치시켜 여기저기 <strong>흩어져 있는 작은 빈 공간들을 하나의 큰 공간</strong>으로 만든다.
      </li>
      <li>
        그러나 압축 방법은 압축하는 과정에서 <strong>시스템은 하던 일을 중지</strong>하고, 메모리에 있는 내용을 <strong>옮기는 작업</strong>은 많은 오버헤드를 야기하며, 어떤 프로세스를 <strong>어떻게 움직여야 오버헤드를 최소화</strong>할 수 있는지 명확한 방법을 결정하기 어렵다는 단점이 있다.
      </li>
    </ul>
  <li>
    압축 이외에 외부 단편화를 없앨 수 있는 해결 방안으로는 <strong>가상 메모리 기법</strong>, 그 중에서도 <strong>페이징 기법</strong>이 있으며 오늘날까지도 사용되는 방법이다.
  </li>
</ul>

<br><br>

<h1>2. 페이징을 통한 가상 메모리 관리</h1>
<ul>
  <li>
    프로세스를 메모리에 연속적으로 할당하는 방식은 앞서 다루었던 외부 단편화 외에도 <strong>물리 메모리보다 큰 프로세스를 실행할 수 없다</strong>는 점이 있다.
  </li>
  <li>
    <strong>가상 메모리(virtual memory)</strong>는 실행하고자 하는 프로그램을 <strong>일부만 메모리에 적재</strong>하여 실제 물리 메모리 크기보다 더 큰 프로세스를 실행할 수 있게 하는 기술이다.
  </li>
    <ul>
      <li>
        가상 메모리 관리 기법에는 크게 <strong>페이징</strong>과 <strong>세그멘테이션</strong>이 있지만, 도서에서는 페이징 기법을 다룬다.
      </li>
    </ul>
</ul>

<br>

<h2>2-1. 페이징이란</h2>
<ul>
  <li>
    <strong>페이징(paging)</strong>은 프로세스의 논리 주소 공간을 <strong>페이지(page)</strong>라는 일정한 단위로 자르고, 메모리 물리 주소 공간을 <strong>프레임(frame)</strong>이라는 페이지와 동일한 크기의 일정한 단위로 <strong>자른 뒤 페이지를 프레임에 할당</strong>하는 가상 메모리 관리 기법이다.
  </li>
  <li>
    페이징에서는 페이지 단위로 스완 아웃, 스왑 인 되며 페이징 시스템에서는 이를 <strong>페이지 아웃(page out)</strong>과 <strong>페이지 인(page in)</strong>이라고 부른다.
  </li>
  <li>
    페이징을 통해 한 프로세스를 실행하기 위해 프로세스 <strong>전체가 메모리에 적재될 필요가 없으며</strong> 프로세스를 이루는 페이지 중 <strong>실행에 필요한 일부</strong> 페이지만 메모리에 적재하고, 당장 실행에 필요하지 않은 페이지들은 <strong>보조기억장치</strong>에 남겨둘 수 있다.
  </li>
</ul>

<br>

<h2>2-2. 페이지 테이블</h2>
<ul>
  <li>
    메모리에 불연속적으로 프로세스가 배치되어 있으면 CPU가 이를 실행할 수가 없다. 따라서 <strong>물리 주소에 불연속적</strong>으로 배체되더라도 <strong>논리 주소에는 연속적</strong>으로 배치되도록 페이지 테이블(page table)을 이용한다.
  </li>
  <li>
    페이지 테이블은 <strong>페이지 번호</strong>와 <strong>프레임 번호</strong>를 짝지어 주는 일종의 이정표이다.
  </li>
    <ul>
      <li>
        CPU는 페이지 번호만 보고 해당 페이지가 적재된 프레임을 찾을 수 있다.
      </li>
    </ul>
  <li>
    프로세스마다 <strong>각자의 프로세스 테이블</strong>을 가지고 있고 각 프로세스의 페이지 테이블들은 <strong>메모리에 적재</strong>되어 있다.
  </li>
    <ul>
      <li>
        CPU 내의 <strong>페이지 테이블 베이스 레지스터(PTBR; Page Table Base Register)</strong>는 각 프로세스의 <strong>페이지 테이블이 적재된 주소</strong>를 가지키고 있다.
      </li>
      <li>
        각 프로세스들의 페이지 테이블 정보들은 <strong>각 프로세스의 PCB</strong>에 기록되며 프로세스의 <strong>문백 교환</strong>이 일어날 때 다른 레지스터와 마찬가지로 함께 변경된다.
      </li>
    </ul>
  <li>
    이렇게 페이지 테이블을 메모리에 두면 생기는 문제는 <strong>메모리 접근 시간이 두 배</strong>로 늘어난다는 점이다.
  </li>
    <ul>
      <li>
        메모리에 있는 페이지 테이블을 확인 → 확인한 프레임에 접근
      </li>
    </ul>
  <li>
    메모리 접근 시간을 단축하기 위해서 CPU 곁에(일반적으로는 MMU 내에) <strong>TLB(Translation Lookaside Buffer)</strong>라는 <strong>페이지 테이블의 캐시 메모리</strong>를 둔다.
  </li>
    <ul>
      <li>
        보편적으로 사용하는 CPU 곁에는 TLB가 있다.
      </li>
      <li>
        TLB는 페이지 테이블의 캐시이기 때문에 페이지 테이블의 일부 내용을 저장한다.
      </li>
    </ul>
  <li>
    CPU가 발생한 논리 주소에 대한 페이지 번호가 TLB에 있는 경우 이를 <strong>TLB 히트(TLB hit)</strong>라고 한다.
  </li>
    <ul>
      <li>
        페이지가 적재된 프레임을 알기 위해 메모리에 접근할 필요가 없다.
      </li>
    </ul>
  <li>
    CPU가 발생한 논리 주소에 대한 페이지 번호가 TLB에 없는 경우 <strong>TLB 미스(TLB miss)</strong>라 하며 이 경우는 <strong>메모리 내의 페이지 테이블에 접근</strong>을 해야한다.
  </li>
</ul>

<h4>내부 단편화</h4>
<ul>
  <li>
    페이징은 외부 단편화 문제를 해결할 수 있지만, <strong>내부 단편화(internal fragmentation)</strong>라는 문제를 야기할 수 있다.
  </li>
  <li>
    프로세스를 일정한 단위로 나눈다 해도 실제로 프로세스의 크기가 <strong>나누어 떨어지는 것이 아니기 때문에</strong> 낭비되는 메모리가 생길 수 있으며 이를 내부 단편화라 한다.
  </li>
  <li>
    내부 단편화는 하나의 페이지 크기보다 작은 크기로 발생한다.
  </li>
    <ul>
      <li>
        하나의 페이지 크기가 작다면 발생하는 내부 단편화의 크기는 작아질 것으로 기대할 수 있다.
      </li>
        <ul>
          <li>
            하지만 너무 페이지 크기가 작다면 페이지 테이블의 크기가 커지기 때문에 페이지 테이블이 차지하는 공간이 낭비된다. 따라서 적당한 크기의 페이지를 설정하는 것이 중요하다.
          </li>
        </ul>
    </ul>
  <li>
    리눅스를 포함한 일부 운영체제는 <strong>기본적으로 설정된 페이지 크기보다 더 큰 크기의 페리지</strong>도 일부 허용하며 메모리에 유지하는 경우도 있다. 이 경우 설저된 페이지보다 큰 페이지를 <strong>대형 페이지(huge page)</strong>라고 한다.
  </li>
</ul>

<br>

<h2>2-3. 페이징에서의 주소 변환(p410)</h2>
<ul>
  <li>
    하나의 페이지 혹은 프레임은 해당하는 연속적인 메모리 주소(여러 주소)를 포괄하고 있다. 따라서 특정 주소에 접근하기 위해서는 아래의 두 가지 정보가 필요하다.
  </li>
    <ol>
      <li>
        <strong>어떤</strong> 페이지 혹은 프레임에 접근하고 싶은지
      </li>
      <li>
        접근하려는 주소가 그 페이지 혹은 프레임으로부터 <strong>얼마나 떨어져</strong> 있는지
      </li>
    </ol>
  <li>
    결국 어떤 위치 그리고 얼마나 떨어져 있는지를 파악하기 위해 페이징 시스템에서는 모든 논리 주소가 기본적으로 <strong>페이지 번호(page number)</strong>와 <strong>변위(offset)</strong>로 이루어져 있다.
  </li>
    <ul>
      <li>
        예를 들어 CPU가 32비트 주소를 보냈다면 이중 N비트는 페이지 번호, 32-N비트는 변위로 설정할 수 있다.
      </li>
      <li>
        페이지 번호는 접근하고자 하는 페이지 번호이며 해당 페이지 번호를 찾으면 페이지가 <strong>어떤 프레임에 할당</strong> 되었는지 알 수 있다.
      </li>
      <li>
        변위는 접근하려는 주소가 프레임의 시작 번지로부터 <strong>얼만큼 떨어져 있는지</strong>를 알기 위한 정보이다.
      </li>
      <li>
        요약하면 논리 주소 &lt페이지 번호, 변위&gt는 페이지 테이블을 통해 물리 주소 &lt프레임 번호, 변위&gt로 변환된다.
      </li>
    </ul>
</ul>

<br>

<h2>2-4. 페이지 테이블 엔트리</h2>
<ul>
  <li>
    페이지 테이블의 각각의 행들을 <strong>a페이지 테이블 엔트리(PTE; Page Table Entry)</strong>a라고 한다.
  </li>
    <ul>
      <li>
        페이지 테이블 엔트리에는 페이지 번호, 프레임 번호도 있지만 대표적으로 중요한 정보들에는 <strong>유효 비트</strong>, <strong>보호 비트</strong>, <strong>참조 비트</strong>, <strong>수정 비트</strong>가 있다.
      </li>
    </ul>
  <li>
    <strong>유효 비트(valid bit)</strong>는 현재 해당 페이지에 <strong>접근 가능한지 여부</strong>를 알려주며 페이지 테이블 엔트리에서 프레임 번호 다음으로 중요한 정보로 볼 수 있다.
  </li>
    <ul>
      <li>
        일반적으로 프로세스를 이루는 모든 페이지가 메모리에 있지 않고 일부 페이지는 보조기억장치(스왑 영역)에 있는 경우가 많다.
      </li>
      <li>
        유효 비트는 현재 페이지가 메모리에 적재되어 있는지(1) 아니면 보조기억장치에 적재되어 있는지(0)를 알려주는 비트이다.
      </li>
      <li>
        CPU가 유효 비트가 0인 메모리에 적재되어 있지 않은 페이지로 접근하려하면 <strong>페이지 폴트(page fault)</strong>라는 예외(Exception)가 발생한다. (페이지 폴트를 처리하는 예는 다음과 같다).
      </li>
        <ol>
          <li>
            CPU는 기존의 작업 내역을 백업한다.
          </li>
          <li>
            페이지 폴트 처리 루틴을 실행한다.
          </li>
          <li>
            페이지 처리 루틴은 원하는 페이지를 메모리로 가져온 뒤 유효 비트를 1로 변경해 준다.
          </li>
          <li>
            페이지 폴트를 처리했다면 CPU는 해당 페이지에 접근할 수 있다.
          </li>
        </ol>
    </ul>
  <li>
    <strong>보호 비트(protection bit)</strong>는 페이지 <strong>보호 기능</strong>을 위해 존재하는 기능이다.
  </li>
    <ul>
      <li>
        보호 비트를 통해 해당 페이지가 읽고 쓰기가 모두 가능한 페이지인지(1) 혹은 읽기만 가능한 페이지인지(0)를 나타낸다.
      </li>
      <li>
        보호 비트는 세 개의 비트로 조금 더 복잡하게 구현할 수도 있다. 읽기(Read)는 r, 쓰기(Write)는 w, 실행(eXecute)는 x의 조합으로 읽기, 쓰기, 실행하기 권한의 조합을 나타낼 수 있다.
      </li>
    </ul>
  <li>
    <strong>참조 비트(reference bit)</strong>는 CPU가 이 페이지에 <strong>접근한 적이 있는지 여부</strong>를 나타낸다. 접근한 적이 있다면 참조 비트가 1로 세팅되고 적재 이후 한 번도 읽거나 쓴 적이 없다면 페이지는 0으로 유지된다.
  </li>
  <li>
    <strong>수정 비트(modified bit)</strong>는 해당 데이터를 <strong>수정한 적</strong>이 있는지 없는지 수정 여부를 알려주며 <strong>더티 비트(dirty bit)</strong>라고도 한다.
  </li>
    <ul>
      <li>
        수정 비트는 페이지가 메모리에서 사라질 때 <strong>보조기억장치</strong>에 쓰기 작업을 해야 하는지, 할 필요가 없는지를 판단하기 위해 존재한다.
      </li>
    </ul>
</ul>

<h4>페이징의 이점-쓰기 시 복사</h4>
<ul>
  <li>
    외부 단편화를 해결하는 것 외에도 페이징이 갖는 이점은 대표적으로 <strong>프로세스 간에 페이지를 공유</strong>할 수 있다는 점이며 대표적인 예로 <strong>쓰기 시 복사(copy on write)</strong>가 있다.
  </li>
  <li>
    예를 들어 부모 프로세스와 동일한 자식 프로세스가 생성되면 부모 프로세스와 동일한 프레임을 갖는다.
  </li>
    <ul>
      <li>
        이때 부모와 자식 중 <strong>어느 하나에 쓰기 작업</strong>을 진행하면 해당 페이지만 별도의 공간으로 복제하며 이를 <strong>쓰기 시 복사</strong>라 한다.
      </li>
    </ul>
</ul>

<h4>계층적 페이징</h4>
<ul>
  <li>
    프로세스를 이루는 <strong>모든 페이지 테이블 엔트리</strong>를 항상 메모리에 유지하는 것은 메모리 낭비이며 <strong>계층적 페이징(hierarchical paging)</strong>은 이 문제를 해결한다.
  </li>
  <li>
    계층적 페이징은 페이지 테이블을 페이징하여 <strong>여러 단계의 페이지</strong>를 두는 방식이다. 여러 단계의 페이지를 둔다는 점에서 <strong>다단계 페이지 테이블(multilevel page table) 기법</strong>이라고도 부른다.
  </li>
  <li>
    페이지 테이블을 계층적으로 나누면 모든 페이지 테이블을 항상 메모리에 유지해야할 필요가 없이 일부는 보조기억장치에 두고 있어도 무방하며 필요하면 적재하면 된다.
  </li>
    <ul>
      <li>
        단, CPU와 가장 가까이 위치한 페이지 테이블(Outer 페이지 테이블)은 항상 메모리에 유지해야 한다.
      </li>
    </ul>
  <li>
    계층적 페이징을 이용하는 환경에서의 논리 주소는 아래와 같은 형태를 가지고 있다.
  </li>
    <ul>
      <li>
        <strong>바깥 페이지 번호</strong>: CPU와 근접한 곳에 위치한(바깥에 위치한) <strong>페이지 테이블 엔트리</strong>를 가리킨다.
      </li>
      <li>
        <strong>안쪽 페이지 번호</strong>: 첫 번째 페이지 테이블 바깥에 위치한 두 번째 페이지 테이블, 즉 <strong>페이지 테이블의 페이지 번호</strong>를 가리킨다.
      </li>
      <li>
        마지막은 변위이다.
      </li>
    </ul>
  <li>
    논리 주소를 기준으로 주소 변환 과정은 다음과 같다.
  </li>
    <ol>
      <li>
        바깥 페이지 번호를 통해 페이지 테이블의 페이지를 찾는다.
      </li>
      <li>
        페이지 테이블의 페이지를 통해 프레임 번호를 찾고 변위를 더하여 물리 주소를 얻는다.
      </li>
    </ol>
  <li>
    페이지 테이블의 계층은 세 개, 네 개, 그 이상이 될 수도 있으나 계층이 늘어날수록 페이지 폴트가 발생했을 경우 메모리 참조 횟수가 많아져 반드시 좋다고 할 수는 없다.
  </li>
</ul>

<br><br>

<h1>3. 페이지 교체와 프레임 할당</h1>
<h2>3-1. 요구 페이징</h2>
<ul>
  <li>
    프로세스를 메모리에 적재할 때 처음부터 모든 페이지를 적재하지 않고 <strong>필요한 페이지만 메모리에 적재</strong>하는 기법을 <strong>요구 페이징(demand paging)</strong>이라고 한다.
  </li>
  <li>
    요구 페이징의 기본적인 양상은 다음과 같다.
  </li>
    <ol>
      <li>
        CPU가 특정 페이지에 접근하는 명령어를 실행한다. 
      </li>
      <li>
        해당 페이지가 현재 메모리에 있을 경우(유효 비트가 1인 경우) CPU는 페이지가 적재된 프레임에 접근한다.
      </li>
      <li>
        해당 페이지가 현재 메모리에 없는 경우(유효 비트가 0인 경우) 페이지 폴트가 발생한다.
      </li>
      <li>
        페이지 폴트 처리 루틴은 해당 페이지를 메모리로 적재하고 유효 비트를 1로 설정한다.
      </li>
      <li>
        다시 1번을 수행한다.
      </li>
    </ol>
  <li>
    아무런 페이지도 <strong>메모리에 적재하지 않을 채 무작정 실행</strong>부터 할 수 있다. 이 경우 프로세스의 첫 명령어를 실행하는 순간부터 페이지 폴트가 계속 발생하지만, 실행에 필요한 페이지가 어느 정도 적재된 이후 <strong>페이지 폴트 발생 빈도가 떨어지며</strong> 이러한 기법을 <strong>순수 요구 페이징(pure demand paging)</strong> 기법 이라 한다.
  </li>
  <li>
    요구 페이징 시스템이 안정적으로 작동하기 위해서는 <strong>페이지 교체</strong>와 <strong>프레임 할당</strong> 두 가지 문제를 해결해야 한다.
  </li>
    <ul>
      <li>
        요구 페이징 기법으로 메모리가 가득 차면 메모리에 적재된 페이지를 보조기억장치로 내보내야 한다. 이때 <strong>어떤 페이지를 내보내는지</strong>를 결정하는 방법을 <strong>페이지 교체 알고리즘</strong>이라 한다.
      </li>
    </ul>
</ul>

<br>

<h2>3-2. 페이지 교체 알고리즘</h2>
<ul>
  <li>
    일반적으로 페이지 폴트를 가장 적게 일으키는 알고리즘을 좋은 알고리즘으로 평가한다.
  </li>
  <li>
    따라서 페이지 교체 알고리즘을 제대로 이해하기 위해서는 <strong>페이지 폴트 횟수</strong>를 알 수 있어야 한다.
  </li>
  <li>
    페이지 폴트 횟수는 <strong>페이지 참조열(page reference string)</strong>을 통해 알 수 있다.
  </li>
    <ul>
      <li>
        페이지 참조열이란 CPU가 참조하는 페이지들 중 <strong>연속된 페이지(같은 페이지)를 생략한 페이지열</strong>을 의미한다.
      </li>
      <li>
        연속된 페이지를 생략하는 이유는 중복된 페이지를 참조하는 행위는 페이지 폴트를 발생시키지 않기 때문이다.
      </li>
        <ul>
          <li>
            페이지 교체 알고리즘을 평가할 때 고려할 것은 오직 페이지 폴트의 발생 횟수기이 때문에 어차피 페이지 폴트가 일어나지 않을 연속된 페이지에 대한 참조는 고려하지 않는다.
          </li>
        </ul>
    </ul>
</ul>

<h3>3-2-1. FIFO 페이지 교체 알고리즘</h3>
<ul>
  <li>
    FIFO 페이지 교체 알고리즘(First-In First-Out Page Replacement Algorithm)은 메모리에 가장 먼저 올라온 페이지부터 내쫓는 방식이다.
  </li>
  <li>
    아이디어와 구현이 간단하지만 어떤 프로그램인지 고려하지 않은 채 무작정 가장 먼저 올라온 페이지부터 정리하기 때문에 긍정적으로 보기 어려운 경우가 많다.
  </li>
</ul>

<h4>2차 기회 페이지 교체 알고리즘</h4>
<ul>
  <li>
    2차 기회 페이지 교체 알고리즘(second chance page replacement algorithm)은 한 번 더 기회를 주는 방식으로 FIFO 페이지 교체 알고리즘의 문제점을 보완한 방법이다.
  </li>
    <ul>
      <li>
        페이지 참조 비트가 1인 경우 당장 내쫓지 않고 참조 비트를 0으로 만든 뒤 현재 시간을 적재 시간으로 설정한다.
      </li>
      <li>
        즉 시간이 가장 오래 되었다면 가장 먼저 들어온 페이지이지만 참조가 있으므로 한 번 시간을 초기화하는 것으로 무마한다.
      </li>
    </ul>
</ul>

<h3>3-2-2. 최적 페이지 교체 알고리즘</h3>
<ul>
  <li>
    최적 페이지 교체 알고리즘(optimal page replacement algorithm)은 CPU에 의해 <strong>참조되는 횟수</strong>를 고려하는 페이지 교체 알고리즘이다. 
  </li>
    <ul>
      <li>
        보조기억장치로 내보내야 할 페이지는 앞으로 <strong>사용 빈도가 가장 낮을 것</strong>이기에 해당 페이지를 교체한다.
      </li>
    </ul>
  <li>
    최적 페이지 교체 알고리즘은 가장 낮은 페이지 폴트율을 보장하는 알고리즘이지만 실제 구현이 어렵다는 문제가 있다.
  </li>
    <ul>
      <li>
        앞으로 오랫동안 사용되지 않을 페이지를 예측하는 것은 어렵다. 
      </li>
    </ul>
  <li>
    주로 다른 페이지 교체 알고리즘의 이론상 성능을 평가하기 위한 목적으로 사용된다. 즉 최적 페이지 교체 알고리즘을 실행했을 때 발생하는 페이지 폴트 횟수를 페이지 폴트의 하한선으로 간주하고, 이에 비해 얼마나 페이지 폴트가 발생했는지 측정하여 평가한다.
  </li>
</ul>

<h3>3-2-3. LRU 페이지 교체 알고리즘</h3>
<ul>
  <li>
    LRU 페이지 교체 알고리즘(LRU; Least Recently Used Page Replacement Altorithm)은 <strong>가장 오랫동안 사용되지 않은 페이지를 교체</strong>하는 알고리즘이다.
  </li>
    <ul>
      <li>
        최근에 사용되지 않은 페이지는 앞으로도 사용되지 않을 것 이라는 아이디어를 토대로 만들어진 알고리즘이다.
      </li>
    </ul>
</ul>

<br>

<h2>3-3. 스레싱과 프레임 할당</h2>
<ul>
  <li>
    프로세스가 실제 실행되는 시간보다 <strong>페이징에 더 많은 시간을 소요</strong>하여 성능이 저해되는 문제를 <strong>스래싱(thrashing)</strong>이라고 한다.
  </li>
    <ul>
      <li>
        너무 빈번한 페이지 교체로 CPU 이용률이 낮아지는 것을 의미한다.
      </li>
    </ul>
  <li>
    메모리에서 동시 실행되는 프로세스의 수를 <strong>멀티프로그래밍 정도(degree of multiprogramming)</strong>이라고 한다. 멀티 프로그래밍의 정도가 높다면 현재 메모리에는 많은 프로세스가 동시에 실행 중이고, 낮다면 현재 메모리에는 적은 프로세스가 동시에 실행 중이라고 이해할 수 있다.
  </li>
    <ul>
      <li>
        멀티프로그래밍 정도가 높아지면 어느 정도까지는 CPU 이용률이 높아지지만, 필요 이상으로 늘리면 각 프로세스들이 사용할 수 있는 프레임 수가 적어지기 때문에 페이지 폴트가 빈번하게 발생하게 되어 CPU 이용률이 떨어지고 성능이 저하된다.
      </li>
    </ul>
  <li>
    가장 단순한 형태의 프레임 할당 방식으로는 각 프로세스에 균등하게 프레임을 할당하는 <strong>균등 할당(equal allocation)</strong> 방식이 있다.
  </li>
    <ul>
      <li>
        단, 균등 할당은 프로세스들의 크기를 고려하지 않고 모두 동일하게 프레임 개수를 할당하기에 합리적이지 못하다.
      </li>
    </ul>
  <li>
    균등 할당 대신 프로세스의 크기에 맞게 프레임을 할당하는 방식을 <strong>비례 할당(proportional allocation)</strong>이라 한다.
  </li>
    <ul>
      <li>
        단, 프로세스의 크기가 커도 막상 많은 프레임을 필요로 하지 않거나 반대로 프로세스의 크기가 작아도 많은 프레임을 필요로 하는 경우도 있어 애매한 부분이 있다.
      </li>
    </ul>
  <li>
    균등 할당과 비례 할당은 프로세스의 실행 과정을 고려하지 않고 단순히 프로세스의 크기와 물리 메모리의 크기만을 고려하는 방식이라는 점에서 <strong>정적 할당 방식</strong>이라고도 한다.
  </li>
  <li>
    프로세스를 <strong>실행하는 과정</strong>에서 배분할 프레임을 결정하는 방식에는 크게 <strong>작업 집합 모델(working set model)</strong>을 사용하는 방식과 <strong>페이지 폴트 빈도(PFF; Page-Fault Frequency)</strong>를 사용하는 방식이 있다.
  </li>
    <ul>
      <li>
        두 방식은 프로세스의 실행을 보고 프레임 수를 결정한다는 점에서 <strong>동적 할당 방식</strong>이라고도 한다.
      </li>
      <li>
        작업 집합 모델 기반의 프레임 할당 방식은 프로세스가 <strong>일정 기간 동안 참조한 페이지 집합</strong>을 기억하여 빈번한 페이지 교체를 방지한다.
      </li>
        <ul>
          <li>
            CPU가 어떤 프로세스를 실행하는 동안 3초에 20개의 페이지를 집중적으로 참조했다면 운영체제는 그 프로세스를 위해 해당 순간만큼은 최소 20개의 프레임을 할당한다.
          </li>
          <li>
            즉 실행 중인 프로세스가 일정 시간 동안 참조한 페이지의 집합을 <strong>작업 집합(working set)</strong>이라고 한다. 따라서 운영체제는 작업 집합의 크기만큼만 프레임을 할당하면 된다.
          </li>
        </ul>
      <li>
        페이지 폴트 빈도를 기반으로 한 프레임 할당은 아래 두 가정에서 생겨난 아이디어이다.
      </li>
        <ol>
          <li>
            페이지 폴트율이 너무 높으면 그 프로세스는 너무 적은 프레임을 갖고 있다.
          </li>
          <li>
            페이지 폴트율이 너무 낮으면 그 프로세스가 너무 많은 프레임을 갖고 있다.
          </li>
        </ol>
      <li>
        페이지 폴트 빈도를 기반으로 한 프레임할당 방식은 페이지 폴트율의 <strong>상한선</strong>과 <strong>하한선</strong>을 정하고 <strong>이 범위 안에서만 프레임</strong>을 할당하는 방식이다.
      </li>
    </ul>
</ul>

<h4>작업 집합 구하기</h4>
<ul>
  <li>
    작업 집합은 실행 중인 프로세스가 일정 시간 동안 참조한 페이지의 집합을 의미하기에 작업 집합을 구하기 위해서는 아래 두 가지가 필요하다.
  </li>
    <ol>
      <li>
        프로세스가 참조한 페이지
      </li>
      <li>
        일정 시간 간격
      </li>
    </ol>
  <li>
    즉 작업 집합은 일정 시간 간격 내에서 프로세스가 참조한 페이지들이다. (중복 제외).
  </li>
</ul>
