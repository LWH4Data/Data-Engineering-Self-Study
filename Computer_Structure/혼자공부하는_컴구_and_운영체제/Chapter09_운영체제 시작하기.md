<h1>1. 운영체제를 알아야 하는 이유</h1>
<h2>1-1. 운영체제란</h2>
<ul>
  <li>
    모든 프프로그램들은 실행에 있어 CPU, 하드 디스크 등 하드웨어를 필요로 하며 이러한 필요 요소들을 <strong>시스템 자원</strong> 혹은 줄여서 <strong>자원</strong>이라 한다.
  </li>
  <li>
    실행할 프로그램에 <strong>필요한 자원을 할당</strong>하고, 프로그램이 <strong>올바르게 실행</strong>되도록 돕는 특별한 프로그램이 <strong>운영체제(operating system)</strong>이다.
  </li>
  <li>
    운영체제 또한 프로그램이기 때문에 실행되기 위해서는 <strong>메모리에 적재</strong>되어야 한다.
  </li>
    <ul>
      <li>
        다만 특별한 프로그램이기 때문에 항상 컴퓨터가 부팅 될 때 메모리 내 <strong>커널 영역(kernel space)</strong>라는 공간에 따로 적재되어 실행된다.
      </li>
      <li>
        커널 영역 외에 나머지 영역과 사용자가 이용하는 응용 프로그램이 적재되는 영역을 <strong>사용자 영역(user space)</strong>이라 한다.
      </li>
      <li>
        운영체제는 커널 영역에 적재되어 사용자 영역에 적재된 프로그램들이 자원을 할당하고 올바르게 실행되도록 돕는다.
      </li>
    </ul>
  <li>
    운영체제는 실행할 프로그램을 메모리에 적재하고, 더 이상 실행되지 않는 프로그램을 메모리에서 삭제하며 지속적으로 <strong>메모리 자원을 관리</strong>한다.
  </li>
    <ul>
      <li>
        최대한 공정하게 여러 프로그램에 <strong>CPU 자원을 할당</strong>한다.
      </li>
      <li>
        동시에 응용 프로그램이 프린터에 접근하는 등 중복되는 활동을 할 때에도 이를 <strong>조율</strong>한다.
      </li>
      <li>
        즉 <strong>응용 프로그램과 하드웨어 사이</strong>에서 응용 프로그램에 필요한 자원을 할당하고, 올바르게 실행되도록 한다.
      </li>
    </ul>
  <li>
    운영체제는 관리할 <strong>자원별로 기능</strong>이 나누어져 있다. 예를 들어 운영체제의 특정 부분은 CPU를, 어느 한 부분은 메모리를, 또 다른 부분은 하드 디스크를 관리하는 등이다.
  </li>
</ul>

<br>

<h2>1-2. 운영체제를 알아야 하는 이유</h2>
<ul>
  <li>
    운영체제가 없다면 하드웨어를 조작하는 코들를 개발자가 모두 직접 작성해야 한다.
  </li>
  <li>
    운영체제는 하드웨어와 가장 긴밀하게 소통하기 때문에 프로그램을 잘 다루기 위해서는, 즉 문제 해결을 잘 하기 위해서는 운영체제를 알아두는 것이 프로그램을 더 깊게 이해할 수 있으며 따라서 운영체제를 알아두는 것은 중요하다.
  </li>
    <ul>
      <li>
        대표적인 예로는 <strong>오류 메시지</strong>가 있다. 하드웨어가 제대로 실행하지 못하면 운영체제는 오류 메시지를 띄워 보여준다.
      </li>
      <li>
        프로그래밍 문법만 학습하는 경우 운영체제의 메시지를 이해하기 어렵고, 이는 문제의 진전과 해결에도 어려움과도 연결된다.
      </li>
    </ul>
</ul>

<br><br>

<h1>2. 운영체제의 큰 그림</h1>
<h2>2-1. 운영체제의 심장, 커널</h2>
<ul>
  <li>
    운영체제는 현존하는 프로그램 중 <strong>규모가 가장 크며</strong> 운영체제의 서비스 또한 <strong>매우 다양</strong>하다.
  </li>
    <ul>
      <li>
        자원에 접근하고 조작하는 기능, 프로그램이 올바르고 안전하게 실행되게 하는 기능이 운영체제의 핵심 서비스이다.
      </li>
    </ul>
  <li>
    운영체제의 핵심 서비스를 담당하는 부분을 <strong>커널(kernel)</strong>이라 한다.
  </li>
    <ul>
      <li>
        운영체제가 설치된 모든 기기에는 커널이 있다.
      </li>
      <li>
        어떤 커널을 사용하는지에 따라 실행하고 개발하는 프로그램이 하드웨어를 이용하는 양상이 달라지고 결과적으로 전체 컴퓨터의 성능도 달라질 수 있다.
      </li>
    </ul>
  <li>
    운영체제가 제공하는 서비스 중 커널에 포함되지 않는 서비스도 있는데, 대표적으로 <strong>사용자 인터페이스(UI, User Interface)</strong>가 속한다.
  </li>
    <ul>
      <li>
        사용자 인터페이스의 종류에는 <strong>그래픽 유저 인터페이스(GUI: Graphical User Interface)</strong>와 <strong>커맨드 라인 인터페이스(CLI: Command Line Interface)</strong>가 있다.
      </li>
        <ul>
          <li>
            그래픽 유저 인터페이스는 바탕화면이나 스마트폰의 화면과 같은 <strong>그래픽</strong>을 기반으로 컴퓨터와 상호작용할 수 있는 인터페이스이다.
          </li>
          <li>
            커맨드 라인 인터페이스는 <strong>명령어</strong>를 기반으로 컴퓨터와 상호작용할 수 있는 인터페이스이다.
          </li>
        </ul>
      <li>
        따라서 같은 커널을 사용하더라도 사용자 인터페이스는 다를 수 있다.
      </li>
    </ul>
</ul>

<br>

<h2>2-2. 이중 모드와 시스템 호출</h2>
<ul>
  <li>
    운영체제는 사용자가 실행하는 응용 프로그램이 하드웨어 자원에 <strong>직접 접근하는 것을 방지</strong>하여 <strong>자원을 보호</strong>한다.
  </li>
    <ul>
      <li>
        즉 응용 프로그램들은 운영체제를 통해서만 자원에 접근이 가능하다.
      </li>
      <li>
        다시 말하면 <strong>운영체제 코드</strong>를 실행하여 응용 프로그램 <strong>대신 요청한 작업을 수행</strong>한다.
      </li>
    </ul>
  <li>
    이런 운영체제의 문지기 역할은 <strong>이중 모드</strong>로 구현된다. 이중 모드(dual mode)란 CPU가 명령어를 실행하는 모드를 크게 <strong>사용자 모드</strong>와 <strong>커널 모드</strong>로 구분하는 방식이다.
  </li>
    <ul>
      <li>
        CPU는 명령어를 <strong>사용자 모드</strong>로써 실행할 수 있고, <strong>커널 모드</strong>로써 실행할 수 있다.
      </li>
    </ul>
  <li>
    <strong>사용자 모드(user mode)</strong>는 운영체제 서비스를 <strong>제공받을 수 </strong> 실행 모드이다. 즉 <strong>커널 영역 코드</strong>를 실행할 수 없다.
  </li>
    <ul>
      <li>
        일반 응용 프로그램은 기본적으로 사용자 모드로 실행된다. 따라서 동일하게 접근이 불가하다.
      </li>
      <li>
        사용자 모드로 실행 중인 CPU는 입출력 명령어와 같은 하드웨어 자원에 접근하는 명령어를 실행할 수 없다.
      </li>
    </ul>
  <li>
    반면 <strong>커널 모드(kernel mode)</strong>는 운영체제 서비스를 제공받을 수 있는 실행 모드이다. 즉 커널 영역의 코드를 실행할 수 있다.
  </li>
    <ul>
      <li>
        CPU가 커널 모드로 명령어를 실행하면 자원에 접근하는 명령어를 비롯해 모든 명령어를 수행할 수 있다.
      </li>
      <li>
        운영체제는 커널 모드로 실행되기 때문에 자원에 접근이 가능하다.
      </li>
    </ul>
  <li>
    CPU가 사용자 모드로 실행 중인지, 커널 모드로 실행 중인지는 <strong>플래그 레지스터 속 슈퍼바이저 플래그</strong>를 보면 알 수 있다.
  </li>
  <li>
    사용자 모드로 실행되는 프로그램이 자원에 접근하는 운영체제 서비스를 제공 받기 위해서는 <strong>운영체제에 요청</strong>을 보내 <strong>커널 모드로 전환</strong>되어야 하며 이를 위해 보내는 요청을 <strong>시스템 호출(system call)</strong>이라 한다.
  </li>
    <ul>
      <li>
        시스템 호출은 일종의 인터럽트이며 이렇게 <strong>특정 명령어</strong>에 의해 발생하는 인터럽트를 <strong>소프트웨어 인터럽트</strong>라 한다.
      </li>
      <li>
        인터럽트의 처리 순서는 4장에서 배운 순서와 유사하다. 하드 디스크 접근의 예를 들면 아래와 같다.
      </li>
        <ol>
          <li>
            하드 디스크에 데이터를 저장하는 시스템 호출을 발생시켜 커널 모드로 전환한다.
          </li>
          <li>
            운영체제 내의 '하드 디스크에 데이터를 저장하는 코드'를 실행하여 하드 디스크에 접근한다.
          </li>
          <li>
            하드 디스크에 접근이 끝났다면 다시 사용자 모드로 복귀하여 실행을 계속한다.
          </li>
        </ol>
    </ul>
  <li>
    일반적으로 응용 프로그램은 실행 과정에서 <strong>운영체제 서비스들을 매우 빈번하게 이용</strong>하며 이 과정에서 빈번하게 <strong>시스템 호출<strong>을 발생시키고 <strong>사용자 모드</strong>와 <strong>커널 모드</strong>를 오간다.
  </li>
</ul>

<br>

<h2>2-3. 운영체제의 핵심 서비스</h2>
<h3>2-3-1. 프로세스 관리</h3>
<ul>
  <li>
    실행 중인 프로그램을 <strong>프로세스(process)</strong>라고 한다. 윈도우의 [작업 관리자]를 열어 [프로세스] 항목을 보면 굉장히 많은 프로세스가 실행 중인 것을 눈으로 확인할 수 있다.
  </li>
  <li>
    CPU는 한 번에 하나의 프로세스만 실행할 수 있기에 CPU는 이 프로세스들을 <strong>조금씩 번갈아 가며 실행</strong>한다.
  </li>
    <ul>
      <li>
        각 프로세스는 상태, 사용하고자 하는 자원이 다양하고 당장 실행할 수 있는 프로세스가 있는가하면 그렇지 않은 프로세스도 있다. 따라서 운영체제는 다양한 프로세스를 일목요연하게 관리하고 실행할 수 있어야 한다.
      </li>
    </ul>
</ul>

<h3>2-3-2. 자원 접근 및 할당</h3>
<ul>
  <li>
    모든 프로세스는 실행을 위해 <strong>자원을 필요</strong>로 하고 운영체제는 프로세스들이 <strong>사용할 자원에 접근하고 조작</strong>함으로써 프로세스에 필요한 자원을 할당한다.
  </li>
</ul>

<h4>2-3-2-1. CPU</h4>
<ul>
  <li>
    일반적으로 메모리에는 여러 프로세스가 적재되고, 하나의 CPU는 한 번에 하나의 프로세스만 실행할 수 있다. 따라서 CPU는 어떤 프로세스부터 CPU를 이용할지, 얼마나 오래 이용할지 등을 결정하는데 이를 <strong>CPU 스케줄링</strong>이라 한다.
  </li>
</ul>

<h4>2-3-2-2. 메모리</h4>
<ul>
  <li>
    메모리에 적재된 프로세스들은 크기와 주소가 가지각색이다. 같은 프로세스라도 실행할 때마다 적재되는 주소가 달라질 수 있으며 따라서 운영체제는 새로운 프로세스가 적재될 때 <strong>어느 주소에 적재</strong>할지를 결정해야 한다.
  </li>
    <ul>
      <li>
        때로는 메모리가 꽉 차있어 꼭 실행해야할 프로세스가 적재될 공간이 없을 수도 있고 공간이 있지만 프로세스를 적재하지 못하는 상황도 발생한다.
      </li>
    </ul>
</ul>

<h4>2-3-2-3. 입출력장치</h4>
<ul>
  <li>
    <strong>인터럽트 서비스 루틴</strong>은 운영체제가 제공하는 기능으로 <strong>커널 영역</strong>에 있으며 입출력장치가 발생시키는 <strong>하드웨어 인터럽트</strong>도 동일한다.
  </li>
    <ul>
      <li>
        CPU가 인터럽트 요청 신호를 받으면 잠시 작업을 멈추고 커널 영역에 있는 인터럽트 서비스 루틴을 실행한다.
      </li>
    </ul>
</ul>

<h3>2-3-3. 파일 시스템 관리</h3>
<ul>
  <li>
    <strong>파일 시스템(file system)</strong>도 운영체제가 지원하는 핵심 서비스이다.
  </li>
</ul>

<h4>가상 머신과 이중 모드의 발전</h4>
<ul>
  <li>
    가상 머신을 통한 가상화를 지원하는 현대 CPU는 <strong>이중 모드(커널 모드와 사용자 모드)이상</strong>을 지원한다.
  </li>
  <li>
    가상 머신(virtual machine)일나 <strong>소프트웨어적으로 만들어낸 가상 컴퓨터</strong>이다.
  </li>
    <ul>
      <li>
        가상 머신을 설치하면 새로운 운영체제와 응용 프로그램을 설치하고 실행할 수 있다.
      </li>
      <li>
        이렇게 설치한 가상 머신 또한 <strong>응용 프로그램</strong>이며 따라서 <strong>사용자 모드</strong>로 작동한다.
      </li>
        <ul>
          <li>
            가상 머신에 설치된 <strong>운영체제 또한 사용자 모드</strong>로 작동한다.
          </li>
        </ul>
    </ul>
  <li>
    가상 머신의 운영체제가 사용자 모드로 작동하면 여러모로 커널 모드로 전환되는 것이 불편하기 때문에 가상화를 지원하는 CPU는 커널 모드와 사용자 모드 외에 가상 머신을 위한 <strong>하이퍼바이저 모드</strong>를 둔다.
  </li>
    <ul>
      <li>
        하이퍼바이저 모드를 통해 가상 머신 상에서 작동하는 응용 프로그램들은 가상 머신에 설치된 운영체제로부터 운영체제 서비스를 받을 수 있다.
      </li>
    </ul>
</ul>
