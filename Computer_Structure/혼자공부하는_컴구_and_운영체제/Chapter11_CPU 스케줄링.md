<h1>1. CPU 스케줄링 개요</h1>
<ul>
  <li>
    운영체제가 프로세스들에게 공정하고 합리적으로 CPU 자원을 배분하는 것을 <strong>CPU 스케줄링(CPU scheduling)</strong>이라고 한다.
  </li>
  <li>
    CPU 스케줄링은 컴퓨터의 성능과도 직결되는 중요한 문제이다.
  </li>
</ul>

<br>

<h2>1-1. 프로세스 우선순위</h2>
<ul>
  <li>
    단순하게 프로세스들이 순서대로 CPU를 용하게 할 수도 있지만 프로세스마다 <strong>우선순위</strong>가 다르기 때문에 좋은 방법은 아니다.
  </li>
    <ul>
      <li>
        일반적으로 프로세스는 CPU와 입출력장치를 모두 사용하는데 <strong>입출력 작업이 많은 프로세스</strong>를 먼저 실행하는 것이 효율적이다.
      </li>
    </ul>
  <li>
    입출력 작업이 많은 프로세스는 <strong>입출력 집중 프로세스(I/O bound process)</strong>라 하고, CPU 작업이 많은 프로세스는 <strong>CPU 집중 프로세스(CPU bound process)</strong>라 한다.
  </li>
    <ul>
      <li>
        입출력 집중 프로세스를 먼저 실행시키면 CPU에 걸리는 부하가 적고 이는 곧 입출력 집중 프로세스가 <strong>입출력 작업을 완료하기 전까지는 대기 상태</strong>가 됨을 의미한다. 따라서 이때 다른 프로세스가 CPU를 사용할 수 있다.
      </li>
    </ul>
  <li>
    상황과 중요도에 맞게 프로세스가 CPU를 이용할 수 있도록 운영체제는 프로세스마다 <strong>우선순위(priority)</strong>를 부여한다.
  </li>
    <ul>
      <li>
        운영체제는 각 프로세스의 <strong>PCB에 우선순위를 명시</strong>하고, PCB에 적인 우선순위를 기준으로 먼저 처리할 프로세스를 결정한다.
      </li>
    </ul>
</ul>

<h4>CPU 버스트와 입출력 버스트</h4>
<ul>
  <li>
    CPU를 이용하는 작업을 <strong>CPU 버스트(CPU burst)</strong>라 하고, 입출력장치를 기다리는 작업을 <strong>입출력 버스트(I/O burst)</strong>라 한다.
  </li>
    <ul>
      <li>
        결과적으로 프로세스는 일반적으로 CPU 버스트와 입출력 버스트를 반복하며 실행된다.
      </li>
    </ul>
</ul>

<h4>프로세스 우선순위 직접 확인하기</h4>
<ul>
  <li>
    우선순위가 높은 대표적인 프로세스는 입출력 작업이 많은 프로세스이지만 이외에도 실시간 프로세스, 일부 백그라운드 프로세스 등이 있다.
  </li>
  <li>
    우선순위는 유닉스, 리눅스, macOS 등의 유닉스 체계 운영체제 에서는 ps -el 명령을 통해 확인이 가능하며 nice 명령을 통해 일부 프로세스의 우선순위를 변경할 수도 있다.
  </li>
</ul>

<br>

<h2>1-2. 스케줄링 큐</h2>
<ul>
  <li>
    프로세스들에는 메모리, 특정 입출력장치, 보조기억장치 등 여러가지 목적을 갖는 프로세스들이 혼재되어 있는데 운영체제가 매번 PCB를 검사하여 프로세스에 자원을 할당하는 것은 번거롭고 시간이 오래 걸린다.
  </li>
  <li>
    따라서 운영체제는 각 프로세스들이 모두 줄을 서서 기다릴 것을 요구하며 이렇게 만들어 지는 줄을 <strong>스케줄링 큐(scheduling queue)</strong>로 구현하고 관리한다.
  </li>
    <ul>
      <li>
        이름은 큐이지만 반드시 선입선출일 필요는 없다.
      </li>
    </ul>
  <li>
    운영체제가 관리하는 <strong>여러 대부분의 자원</strong>들은 이렇게 큐로 관리된다.
  </li>
    <ul>
      <li>
        예를 들면 CPU를 사용하려는 프로세스의 스케줄링 큐, 하드 디스크를 사용하려는 프로세스의 스케줄링 큐, 프린터를 사용하려는 프로세스의 스케줄링 큐 등이 있다.
      </li>
    </ul>
  <li>
    대표적인 큐로는 <strong>준비 큐(ready queue)</strong>와 <strong>대기 큐(waiting queue)</strong>가 있다. 준비 큐는 <strong>CPU를 이용하고 싶은 프로세스들</strong>이 서는 줄이고, 대기 큐는 <strong>입출력장치</strong>를 이용하기 위해 <strong>대기 상태에 접어든 프로세스</strong>들이 서는 줄을 의미한다.
  </li>
  <li>
    우선순위가 낮은 프로세스들이 먼저 큐에 삽입되어 줄을 서고 있다 해도 <strong>우선순위가 높은 프로세스</strong>가 들어오면 먼저 처리가 될 수 있다.
  </li>
    <ul>
      <li>
        대기 상태의 프로세스도 동일하게 작동한다. 입출력이 완료되어 완료 인터럽트가 발생하면 운영체제는 대기 큐에서 작업이 완료된 PCB를 찾고 해당 PCB를 <strong>준비 상태로 변경한 뒤 대기 큐에서 제거</strong>한다.
      </li>
    </ul>
</ul>

<br>

<h2>1-3. 선점형과 비선점형 스케줄링</h2>
<ul>
  <li>
    <strong>선점형 스케줄링(preemptive scheduling)</strong>은 프로세스가 CPU를 비롯한 자원을 사용하고 있더라도 운영체제가 프로세스로부터 <strong>자원을 강제로 빼앗아</strong> 다른 프로세스에 할당할 수 있는 스케줄링 방식이다.
  </li>
    <ul>
      <li>
        지금까지 설명한 스케줄링 방식이 선점형 스케줄링의 일종이다. 프로세스마다 정해진 시간만큼 CPU를 사용하고, 정해진 시간을 모두 소비하여 타이머 인터럽트가 발생하면 운영체제가 해당 프로세스로부터 CPU 자원을 빼앗아 다음 프로세스에 할당한다.
      </li>
    </ul>
  <li>
    <strong>비선점형 스케줄링(non-preemptive scheduling)</strong>이란 하나의 프로세스가 자원을 사용하고 있다면 해당 프로세스가 종료되거나 스스로 대기 상태에 접어들기 전까지 <strong>다른 프로세스가 끼어들 수 없는 스케줄링 방식</strong>이다.
  </li>
    <ul>
      <li>
        쉽게 말해 <strong>자원을 독점</strong>하는 방식이다.
      </li>
    </ul>
</ul>

<br><br>

<h1>2. CPU 스케줄링 알고리즘</h1>
<ul>
  <li>
    CPU 스케줄링 알고리즘의 종류는 매우 다양하고 운영체제마다 서로 다른 스케줄링 알고리즘을 사용한다.
  </li>
  <li>
    중요한 것은 스케줄링 알고리즘에서 사용된 아이디어이지 용어가 아니며 암기보다 이해에 집중한다.
  </li>
</ul>

<br>

<h2>2-1. 스케줄링 알고리즘의 종류</h2>
<h3>2-1-1. 선입 선처리 스케줄링</h3>
<ul>
  <li>
    <strong>선입 선처리 스케줄링</strong>은 <strong>FCFS 스케줄링(First Come First Served Scheduling)</strong>이라고도 부르며 단순히 준비된 큐에 삽입된 순서대로 프로세스들을 처리하는 <strong>비선점형 스케줄링 방식</strong>이다.
  </li>
  <li>
    때때로 프로세스들이 기다리는 시간이 매우 길어질 수 있다는 부작용이 있다.
  </li>
    <ul>
      <li>
        예를 들어 프로세스 A가 17ms, B가 5ms, C가 2ms 동안 CPU를 이용하는데 A → B → C 순으로 프로세스가 처리된다면 C는 고작 2ms를 위해 17ms + 5ms를 대기해야한다. 이와 같은 현성을 <strong>호위 효과(convoy effect)</strong>라 한다.
      </li>
    </ul>
</ul>

<h3>2-1-2. 최단 작업 우선 스케줄링</h3>
<ul>
  <li>
    <strong>CPU 이용 시간의 길이가 가장 짧은 프로세스</strong>부터 실행하는 스케줄링 방식을 <strong>최단 작업 우선 스케줄링</strong> 혹은 <strong>SJF 스케줄링(Shortest Job First Scheduling)</strong>이라 한다.
  </li>
    <ul>
      <li>
        CPU 이용 시간을 기준으로 하기 때문에 호위 효과를 방지할 수 있다.
      </li>
    </ul>
  <li>
    기본적으로 비선점형 스케줄링 알고리즘이지만 선점형으로 구현될 수도 있으며 이것이 후술할 선점형 최단 작업 우선 스케줄링이다.
  </li>
</ul>

<h3>2-1-3. 라운드 로빈 스케줄링</h3>
<ul>
  <li>
    라운드 로빈 스케줄링(round robin scheduling)은 선입 선처리 스케줄링에 <strong>타임 슬라이스</strong>라는 개념이 더해진 스케줄링 방식이다.
  </li>
    <ul>
      <li>
        타임 슬라이스란 각 프로세스가 <strong>CPU를 사용할 수 있는 정해진 시간</strong>을 의미한다.
      </li>
      <li>
        정해진 시간(타임 슬라이스)만큼만 CPU를 이용하고 정해진 시간 내에 완료되지 못한 경우 <strong>다시 큐의 가장 뒤에 삽입</strong>된다.
      </li>
    </ul>
  <li>
    타임 슬라이스의 크기가 매우 중요하다.
  </li>
    <ul>
      <li>
        타임 슬라이스가 너무 크면 사실상 선입 선처리 스케줄링과 다를 바가 없다.
      </li>
      <li>
        반대로 타임 슬라이스가 너무 작으면 문맥 교환에 발생하는 비용이 커 CPU는 프로세스를 처리하는 일보다 <strong>프로세스를 전환</strong>하는 데 많은 비용을 사용한다.
      </li>
    </ul>
</ul>

<h3>2-1-4. 최소 잔여 시간 우선 스케줄링</h3>
<ul>
  <li>
    <strong>최소 잔여 시간 우선 스케줄링</strong> 혹은 <strong>SRT(Shortest Remaining Time) 스케줄링</strong>은 최단 작업 우선 스케줄링 알고리즘과 라운드 로빈 알고리즘을 합친 스케줄링 방식이다.
  </li>
  <li>
    작동 방식은 프로세스들은 정해진 타임 슬라이스만큼 CPU를 사용하되, CPU를 사용할 다음 프로세스는 <strong>남아있는 작업 시간이 가장 적은 프로세스</strong>가 된다.
  </li>
</ul>

<h3>2-1-5. 우선순위 스케줄링</h3>
<ul>
  <li>
    우선순위 스케줄링(priority scheduling)은 프로세스들에 <strong>우선순위</strong>를 부여하고, 가장 높은 우선순위를 가진 프로세스부터 실행하는 스케줄링 알고리즘이다.
  </li>
   <ul>
     <li>
       우선순위가 같은 프로세스들은 선입 선처리로 스케줄링된다.
     </li>
     <li>
       최단 작업 우선 스케줄링과 최소 잔여 시간 우선 스케줄링 알고리즘은 넓은 의미에서 우선순위 스케줄링의 일종으로 볼 수 있다.
     </li>
   </ul>
  <li>
    우선순위 스케줄링은 우선순위가 낮은 프로세스들이 <strong>계속해서 실행이 연기</strong>될 수 있는 문제가 있는데 이를 <strong>기아(starvation) 현상</strong>이라 한다.
  </li>
    <ul>
      <li>
        이를 방지하기 위한 대표적인 기법으로 <strong>에이징(aging)</strong>이 있다. 에이징은 오랫동안 대기한 프로세스의 우선순위를 점차 높이는 방식이다.
      </li>
    </ul>
</ul>

<h3>2-1-6. 다단계 큐 스케줄링</h3>
<ul>
  <li>
    다단계 큐 스케줄링(multilevel queue scheduling)은 우선순위 스케줄링이 발전항 형태로 <strong>우선순위별로 준비 큐를 여러 개 사용</strong>하는 스케줄링 방식이다.
  </li>
    <ul>
      <li>
        우선순위가 가장 높은 큐에 있는 프로세스들을 먼저 처리한다. 만약 해당 큐가 비어있다면 그다음 우선순위 큐에 있는 프로세스들을 처리한다.
      </li>
    </ul>
  <li>
    이렇게 큐를 여러 개 두면 <strong>프로세스 유형별</strong>로 우선순위를 구분하여 실행하는 것이 편리해진다.
  </li>
    <ul>
      <li>
        예를 들어 특정 큐에는 우선순가 비교적 높아야하는 CPU 집중 프로세스를, 또 다른 큐에는 우선순위가 비교적 낮아도 되는 입출력 집중 프로세스를 삽입할 수 있다.
      </li>
      <li>
        큐별로 타임 슬라이스를 여러 개 지정하거나 큐마다 다른 스케둘링 알고리즘을 사용할 수도 있다.
      </li>
    </ul>
</ul>

<h3>2-1-7. 다단계 피드백 큐 스케줄링</h3>
<ul>
  <li>
    <strong>다단계 피드백 큐 스케줄링(multilevel feedback queue schduling)</strong>은 다단계 큐 스케줄링의 발전된 형태로 다단계 큐 스케줄링이 프로세스들이 큐 사이를 이동할 수 없어 <strong>다시 한번 기아 상태가 발생할 수 있는 문제를 보완</strong>한다.
  </li>
  <li>
    핵심적인 개선점은 프로세스들이 <strong>큐 사이를 이동</strong>할수 있다는 점이다.
  </li>
    <ul>
      <li>
        새로 준비 상태가된 프로세스는 우선순위가 높은 우선순위 큐에 일정 시간 실행된다.
        <br>→ 만약 프로세스가 해당 큐에서 실행이 끝나지 않으면 다음 우선순위 큐에 삽입되어 실행된다.
        <br>→ 위의 과정을 반복하며 CPU를 비교적 오래 사용해야 하는 CPU 집중 프로세스들은 자연스럽게 우선순위가 낮아진다.
        <br>→ 반면 CPU를 비교적 적게 사욯아는 입출력 집중 프로세스들은 자연스럽게 우선순위가 높은 큐에서 실행이 끝난다.
      </li>
    </ul>
  <li>
    반대로 낮은 우선순위 큐에서 너무 오래 기다리는 프로세스가 있다면 점차 우선순위가 높은 큐로 이동시키는 <strong>에이징 기법</strong>을 적용하여 기아 현상을 방지할 수 있다.
  </li>
  <li>
    결론적으로 CPU 이용 시간이 너무 길면 낮은 우선순위 큐로 이동시키고, 낮은 우선순위 큐에서 너무 오래 기다리는 프로세스가 있다면 에이징을 통해 다시 높은 우선순위 큐로 이동시키면서 <strong>양방향으로 작동</strong>한다.
  </li>
  <li>
