<h1>1. 교착 상태란</h1>
<h2>1-1. 식사하는 철학자 문제</h2>
<ul>
  <li>
    <strong>식사하는 철학자 문제(dining philosophers problem)</strong>은 교착 상태를 설명하기 위한 고전적이고 재미있는 문제 상황이다. (p368).
  </li>
  <li>
    프로세스는 자원 A를 점유한 채 웹 브라우저 프로세스가 점유하고 있는 자원 B의 사용이 끝나길 기다리고, 웹 브라우저 프로세스는 자원 B를 점유핸 채 게임 프로세스의 자원 A 사용이 끝나길 기다리며 진행이 멈춰 버리는 현상을 <strong>교착 상태(deadlock)</strong>이라 한다.
  </li>
  <li>
    교착 상태를 해결하기 위해서는 두 가지 근본적인 이유에 대해 알아야한다.
  </li>
    <ul>
      <li>
        첫째, 교착 상태가 발생했을 때의 <strong>상황</strong>을 정확히 표현해 본다.
      </li>
      <li>
        둘째, 교착 상태가 일어나는 근본적인 <strong>이유</strong>에 대해 알아본다.
      </li>
    </ul>
</ul>

```text
// 1. 교착 상태(lock1).
lock1 = true;
while (lock2 == true)
;
// 임계 구역 작업
lock1 = false;
```

```text
// 2. 교착 상태(lock2)
lock2 = true;
while (lock1 == true)
;
// 임계 구역 작업
lock2 = false;
```

<h2>1-2. 자원 할당 그래프</h2>
<ul>
  <li>
    교착 상태는 자원 할당 그래프(resource-allocation graph)를 통해 단순하게 표현할 수 있다.
  </li>
  <li>
    자원 할당 그래프는 어떤 프로세스가 <strong>어떤 자원을 사용</strong>하고 있고, 어떤 프로세스가 <strong>어떤 자원을 기다리고 있는지</strong>를 표현한 그래프이다.
  </li>
  <li>
    교착 상태가 발생한 상황은 자원 할당 그래프가 <strong>원의 형태</strong>를 띄고 있다.
  </li>
</ul>

<h3>1-2-1. 첫째, 프로세스는 원으로, 자원의 종류는 사각형으로 표현한다</h3>
<ul>
  <li>
    말 그대로 프로세스는 원, 자원은 사각형으로 표현한다.
  </li>
</ul>

<h3>1-2-2. 둘째, 사용할 수 있는 자원의 개수는 자원 사각형 내에 점으로 표현한다</h3>
<ul>
  <li>
    <strong>같은 자원</strong>이라 해도 사용 가능한 <strong>자원의 개수는 여러 개</strong> 있을 수 있다.
  </li>
    <ul>
      <li>
        예를 들어 자원의 종류는 하드 디스크 하나이지만, 사용 가능한 하드 디스크 개수는 세 개이면 사각형(자원) 내에 세 개의 점으로 표현할 수 있다.
      </li>
    </ul>
</ul>

<h3>1-2-3. 셋째, 프로세스가 어떤 자원을 할당받아 사용 중이라면 자원에서 프로세스를 향해 화살표를 표시한다</h3>
<ul>
  <li>
    자원에서 프로세스로 화살표를 그리며 프로세스가 자원 이용을 끝내고 운영체제에 <strong>자원을 반납</strong>하면 <strong>화살표는 삭제</strong>된다.
  </li>
</ul>

<h3>1-2-4. 넷째, 프로세스가 어떤 자원을 기다리고 있다면 프로세스에서 자원으로 화살표를 표시한다</h3>
<ul>
  <li>
    표현 그대로 자원을 기다리는 프로세스에서 가디라고 있는 자원으로 화살표를 그린다.
  </li>
</ul>

<br>

<h2>1-3. 교착 상태 발생 조건</h2>
<ul>
  <li>
    교착 상태가 발생하는 조건에는 <strong>상호 배제</strong>, <strong>점유와 대기</strong>, <strong>비선점</strong>, <strong>원형 대기</strong> 네 가지가 있다.
  </li>
  <li>
    조건 중 하나라도 만족하지 않는다면 교착 상태가 발생하지 않지만, 조건이 모두 만족될 때 교착 상태가 발생할 가능성이 높다.
  </li>
</ul>

<h3>1-3-1. 상호 배제</h3>
<ul>
  <li>
    한 프로세스가 사용하는 자원을 다른 프로세스가 사용할 수 없을 때, 즉 상호 배제(mutual exclusion) 상황에서 교착 상태가 발생할 수 있다.
  </li>
</ul>

<h3>1-3-2. 점유와 대기</h3>
<ul>
  <li>
    자원을 할당받은 상태에서 다른 자원을 할당받기를 기다리는 상태를 점유와 대기(hold and wait)이라 한다.
  </li>
</ul>

<h3>1-3-3. 비선점</h3>
<ul>
  <li>
    비선점(nonpreemptive) 자원은 해당 자원을 이용하는 프로세스의 작업이 끝나야만 비로소 이용할 수 있다.
  </li>
  <li>
    즉 어떤 프로세스도 다른 프로세스의 자원을 강제로 빼앗지 못해 교착 상태가 발생한다.
  </li>
</ul>

<h3>1-3-4. 원형 대기</h3>
<ul>
  <li>
    프로세스들이 원의 형태로 자원을 대기하는 것을 원형 대기(circular wait)이라 한다.
  </li>
  <li>
    단, 자원 할당 그래프가 원의 형태를 띈다고 해서 무조건 교착 상태가 발생하는 것은 아니다.
  </li>
</ul>

<br><br>

<h1>2. 교착 상태 해결 방법</h1>
<ul>
  <li>
    교착 상태를 해결하는 방법에는 크게 세 가지가 있다.
  </li>
    <ul>
      <li>
        첫째, 애초에 교착 상태가 일어나지 않도록 교착 상태 발생 조건에 부합하지 않게 자원을 분배하여 교착 상태를 <strong>예방</strong>한다.
      </li>
      <li>
        둘째, 교착 상태가 발생하지 않을 정도로 조금씩 자원을 할당하다가 교착 상태의 위험이 있다면 자원을 할당하지 않는 방식으로 교착 상태를 <strong>회피</strong>한다.
      </li>
      <li>
        셋째, 자원을 제약 없이 할당하다가 교착 상태가 검출되면 교착 상태를 <strong>회복</strong>한다.
      </li>
    </ul>
</ul>
