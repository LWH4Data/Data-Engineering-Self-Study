<h1>1. 동기화란</h1>
<ul>
  <li>
    동시다발적으로 실행되는 프로세스들은 공동의 목적을 수행하기 위해 <strong>실행 순서와 자원의 일관성</strong>을 보장해야하며 따라서 반드시 <strong>동기화(synchronization)</strong>되어야 한다.
  </li>
</ul>

<br>

<h2>1-1. 동기화의 의미</h2>
<ul>
  <li>
    동시다발적으로 실행되는 많은 프로세스는 서로 데이터를 주고받으며 협력하며 실행될 수 있기에 올바른 실행을 위해 동기화가 필요하다.
  </li>
  <li>
    프로세스 동기화란 프로세스들 사이의 <strong>수행 시기</strong>를 맞추는 것을 의미한다. 수행 시기를 맞춘다는 것은 크게 아래의 두 가지를 의미한다.
  </li>
    <ul>
      <li>
        <strong>실행 순서 제어</strong>: 프로세스를 <strong>올바른 순서</strong>대로 실행한다.
      </li>
      <li>
        <strong>상호 배제</strong>: 동시에 접근해서는 안 되는 자원에 <strong>하나의 프로세스만 접근</strong>하게 한다.
      </li>
    </ul>
  <li>
    프로세스 뿐만 아니라 스레드를 포함해 <strong>실행의 흐름을 갖는 모든 것</strong>은 동기화의 대상이된다.
  </li>
</ul>

<h3>1-1-1. 첫째, 실행 순서 제어를 위한 동기화</h3>
<ul>
  <li>
    Writer 프로세스와 Reader 프로세스가 <strong>동시에 실행 가능한 상태</strong>에 있을 때, Reader 프로세스는 Writer 프로세스의 실행이 끝난 뒤에 실행되어야 한다. 이처럼 동시에 실행될 수 있는 프로세스들 사이에서 <strong>필요한 실행 순서를 보장</strong>하는 것이 프로세스 동기화의 한 예이다.
  </li>
</ul>

<h3>1-1-2. 둘째, 상호 배제를 위한 동기화</h3>
<ul>
  <li>
    상호 배제(mutual exclusion)는 공유가 불가능한 자원의 <strong>동시 사용을 피하기 위해</strong> 사용하는 알고리즘이다.
  </li>
  <li>
    상호 배제를 하지 않으면 DB에서 Lost Update가 발생하는 것처럼 중간 과정이 무시되는 문제가 발생할 수도 있다.
  </li>
</ul>

<br>

<h2>1-2. 생상자와 소비자 문제</h2>
<ul>
  <li>
    상호 배제를 위한 동기화에 대해 조금더 알아보면 생산자와 소비스자 문제가 있다. <strong>계속해서 생산하는 프로세스인 생산자</strong>와 <strong>계속해서 소비하는 프로세스인 소비자</strong>로 이루어진다.
  </li>
  <li>
    생산자와 소비자는 '총합'이라는 데이터를 공유한다. 생산자는 버퍼에 물건을 넣고 물건의 총합을 1 증가시키고, 소비자는 버퍼에 물건을 빼고 총합을 1 감소시킨다.
  </li>
    <ul>
      <li>
        생산자와 소비자를 동시에 수행하는 것을 반복하면 결과가 예상과 다르게 나오는 것을 볼 수 있다. 보통 생산자가 소비자 작업이 끝나기 전에 총합을 수정했기 때문이며 이 문제는 DB에서 발생하는 문제와 동일하다.
      </li>
    </ul>
</ul>

```text
생산자 () {
    버퍼에 데이터 삽입
    '총합' 변수 1 증가
}
```

```text
소비자 () {
    버퍼에서 데이터 빼내기
    '총합' 변수 1 감소
}
```

```text
물건 총합 계산.
총합 = 10

생산자 () {
    버퍼에 데이터 삽입
    '총합' 변수 1 증가
}
소비자 () {
    버퍼에서 데이터 빼내기
    '총합' 변수 1 감소
}
```

<br>

<h2>1-3. 공유 자원과 임계 구역</h2>
<ul>
  <li>
    동시에 실행되는 프로세스들이 공동의 자원을 두고 작업을 할 때 이러한 자원을 <strong>공유 자원(shared resource)</strong>이라고 한다.
  </li>
    <ul>
      <li>
        공유 자원은 전역 변수가 될 수도 있고, 파일, 입출력장치, 보조기억장치 등이 될 수도 있다.
      </li>
    </ul>
  <li>
    동시에 실행하면 문제가 발생하는 자원에 접근하는 코드 영역을 <strong>임계 구역(critical section)</strong>이라 한다.
  </li>
    <ul>
      <li>
        두 개 이상의 프로세스가 임계 구역에 진입하고자 하면 <strong>둘 중 하나는 대기</strong>해야 한다.
      </li>
    </ul>
  <li>
    임계 구역은 두 개 이상의 프로세스가 동시에 실행되면 안 되는 영역이지만, 잘못된 실행으로 여러 프로세스가 동시 다발적으로 임계 구역의 코드를 실행하여 문제가 발생할 수 있으며 이를 <strong>레이스 컨디션(race condition)</strong>이라 한다.
  </li>
    <ul>
      <li>
        레이스 컨디션이 발생하면 데이터의 일관성이 깨지는 문제가 발생한다.
      </li>
      <li>
        예를 들면 고급언어를 저급언어로 변환하여 수행하는 과정에서 문백 교환이 발생할 수도 있으며 이러한 경우 상호 배제를 위한 동기화가 관리를 한다.
      </li>
    </ul>
  <li>
    운영체제는 임계 구역 문제를 아래의 세 가지 원칙 하에 해결한다.
  </li>
    <ul>
      <li>
        <strong>상호 배제(mutual exclusion)</strong>: 한 프로세스가 임계 구역에 진입했다면 다른 프로세스는 임계 구역에 들어올 수 없다.
      </li>
      <li>
        <strong>진행(progress)</strong>: 임계 구역에 어떤 프로세스도 진입하지 않았다면 임계 구역에 진입하고자 하는 프로세스는 들어갈 수 있어야 한다.
      </li>
      <li>
        <strong>유한 대기(bounded waiting)</strong>: 한 프로세스가 임계 구역에 진입하고 싶다면 그 프로세스는 언젠가는 임계 구역에 들어올 수 있어야 한다.
      </li>
    </ul>
</ul>

<h1>2. 동기화 방법</h1>
<h2>2-1. 뮤텍스 락</h2>
<ul>
  <li>
    <strong>뮤텍스 락(Mutex lock; MUTual EXclusion lock)</strong>은 상호 배제를 위한 동기화 도구로 실행 중인 프로세스가 <strong>임계 구역을 잠그고</strong> 다른 프로세스는 임계 구역이 잠겨 있다면 대기, 잠겨있지 않다면 임계 구역에 진입한다.
  </li>
  <li>
    뮤텍스 락의 매우 단순한 형태는 하나의 전역 변수와 두 개의 함수로 구현할 수 있다.
  </li>
    <ul>
      <li>
        자물쇠 역할: 프로세스들이 공유하는 전역 변수 lock
      </li>
      <li>
        임계 구역을 잠그는 역할: acquire 함수
      </li>
        <ul>
          <li>
            프로세스가 임계 구역에 진입하기 전에 호출하는 함수이다.
          </li>
            <ul>
              <li>
                임계 구역이 잠겨 있다면(lock = false가 될 때까지) 임계 구역을 반복적으로 확인하며 이러한 대기 방식을 <strong>바쁜 대기(busy wait)</strong>이라 한다.
              </li>
              <li>
                암계 규역이 열려 있다면 임계 구역을 잠근다(lock = true로 바꾼다).
              </li>
            </ul>
        </ul>
      <li>
        임계 구역의 잠금을 해제하는 역할: release 함수
      </li>
        <ul>
          <li>
            임계 구역에서의 작업이 끝나고 호출하는 함수이다.
          </li>
          <li>
            임계 구역을 열어주는(lock = false로 바꾸는) 함수이다.
          </li>
        </ul>
    </ul>
  <li>
    실제 C/C++, python 등의 일부 프로그래밍 언어는 사용자가 직접 acquire, release 함수를 구현하지 않아도되도록 뮤텍스 락 기능을 제공한다.
  </li>
</ul>

```text
acquire() {
    while(lock == true)  /* 만약 임계 구역이 잠겨 있다면 */
        ;                /* 임계 구역이 잠겨 있는지를 반복적으로 확인 */
    lock = true          /* 만약 임계 구역이 잠겨 있지 않다면 임계 구역 잠금 */
}

release() {
    lock = false;        /* 임계 구역 작업이 끝났으니 잠금 해제 */
}
```

```text
acquire();    // 자물쇠 잠겨 있는지 확인, 잠겨 있지 않다면 잠그고 들어가기
// 임계 구역   // 임계 구역에서의 작업 진행
release();    // 자물쇠 반환 
```

<h2>2-2. 세마포</h2>
<ul>
  <li>
    <strong>세마포(semaphore)</strong>는 뮤텍스 락과 비슷하지만 조금 더 일반화된 방식의 동기화 도구이다. 즉 뮤텍스 락은 하나의 공유 자원에 접근하는 프로세스를 상정하는 방식이지만 세마포는 <strong>공유 자원이 여러 개</strong> 있는 상황에도 적용이 가능하다.
  </li>
    <ul>
      <li>
        엄밀히 말하면 세마포의 종류에도 이진 세마포(binary semaphore)와 카운팅 세마포(counting semaphore)가 있다. 도서에서 다루는 것은 카운팅 세마포이다.
      </li>
    </ul>
  <li>
    세마포를 사용하면 프로세스는 임계 구역 앞에서 멈춤 신호를 받으면 잠시 기다리고, 가도 좋다는 신호를 받으면 임계 구역에 들어간다.
  </li>
  <li>
    세마포는 뮤텍스 락과 비슷하게 하나의 변수와 두 개의 함수로 단순하게 구현할 수 있다.
  </li>
    <ul>
      <li>
        임계 구역에 진입할 수 있는 프로세스의 개수(사용 가능한 공유 자원의 개수)를 나타내는 <strong>전역 변수 S</strong>
      </li>
      <li>
        입계 구역에 들어가도 좋은지, 기다려야 할지를 알려주는 <strong>wait 함수</strong>
      </li>
        <ul>
          <li>
            사용할 수 있는 자원(S)이 없을 경우 해당 프로세스를 <strong>대기 상태</strong>로 만들고 PCB를 세마포를 위한 <strong>대기 큐에 삽입</strong>한다.
          </li>
        </ul>
      <li>
        임계 구역 앞에서 기다리는 프로세스에 '이제 가도 좋다'고 신호를 주는 <strong>signal 함수</strong>
      </li>
        <ul>
          <li>
            대기 중인 프로세스를 <strong>대기 큐에서 제거</strong>하고, 프로세스 상태를 준비 상태로 변경한 뒤 <strong>준비 큐</strong>로 옮긴다.
          </li>
        </ul>
    </ul>
  <li>
    세마포를 이용해 프로세스의 순서를 제어하는 방법은 세마포의 변수 S를 0으로 두고 <strong>먼저 실행할 프로세스 뒤에 signal 함수</strong>를, <strong>다음에 실행할 프로세스 앞에 wait 함수</strong>를 붙이면 된다.
  </li>
    <ul>
      <li>
        어떤 프로세스가 먼저 실행되는가에 상관없이 wait() 함수가 앞에 있는 프로세스는 후에 실행되기 때문에 우선순위가 조정된다.
      </li>
    </ul>
</ul>

```text
wait() {
    S--;
    if ( S < 0 ) {
        add this process to Queue;
        sleep();
    } 
}
```

```text
signal() {
    S++
    if ( S <= 0) {
        remove a process p from Queue
        wakeup(p)
    }
}
```

<h2>2-3. 모니터</h2>
<ul>
  <li>
    세마포는 매번 wait()과 signal() 함수를 명시해야하며 코드가 방대해지면 함수의 순서 등이 헷갈릴 수 있는 불편함이 있다. <strong>모니터(monitor) 방식</strong>은 세마포의 이런 불편함을 완화해주는 방법이다. 
  </li>
  <li>
    모니터는 자원과 공유 자원에 접근하기 위한 <strong>인터페이스(통로)를 묶어서 관리</strong>한다.
  </li>
    <ul>
      <li>
        프로세스는 반드시 <strong>인터페이스를 통해서만 공유 자원에 접근</strong>하도록한다.
      </li>
      <li>
        모니터를 통해 공유 자원에 접근하고자 하는 프로세스를 큐에 삽입하고 큐에 삽입된 순서대로 하나씩 공유 자원을 이용하도록 한다.
      </li>
    </ul>
  <li>
    요약하면 모니터는 공유 자원을 다루는 <strong>인터페이스에 접근하기 위한 큐(모니터에 진입하기 위한 큐)</strong>를 만들고, 모니터 안에 <strong>항상 하나의 프로세스</strong>만 들어오도록 하여 <strong>상호 배제를 위한 동기화</strong>를 제공한다.
  </li>
  <li>
    모니터는 실행 순서를 제어하기 위한 동기화로 <strong>조건 변수(condition variable)</strong>를 사용한다. (조건 변수와 모니터는 별개의 개념이다).
  </li>
    <ul>
      <li>
        조건 변수는 <strong>프로세스나 스레드의 실행 순서</strong>를 제어하기 위해 사용하는 특별한 변수이다.
      </li>
      <li>
        조건 변수로는 wait()와 signal() 연산을 수행할 수 있다.
      </li>
        <ul>
          <li>
            wait는 호출한 프로세스의 상태를 대기 상태로 전황하고 일시적으로 조견 변수에 대한 대기 큐에 삽입하는 연산이다.
          </li>
          <li>
            모니터에 진입하는 큐와 wait가 호출되어 실행이 중단된 프로세스들이 삽입되는 큐는 다르다. 
          </li>
            <ul>
              <li>
                모니터에 진입하는 큐는 모니터에 한 번에 하나의 프로세스만 <strong>진입</strong>하도록 하기 위해 만들어진 큐이다.
              </li>
              <li>
                wait 호출로 인한 조건 변수에 대한 대기 큐는 이미 진입한 프로세스의 실행 조건이 만족될 때까지 <strong>잠시 실행이 중단되어 기다리기 위해 만들어진 큐</strong>이다.
              </li>
            </ul>
          <li>
            wait() 연산으로 일시 중지된 프로세스는 signal() 연산을 통해 실행이 재개될 수 있다.
          </li>
        </ul>
      <li>
        <strong>모니터 안에는 하나의 프로세스</strong>만 있을 수 있기 때문에 wait를 호출했던 프로세스는 signal을 호출한 프로세스가 모니터를 떠난 뒤에 실행되거나, signal을 호출한 프로세스의 실행을 일시 중단하고 자신이 실행된 뒤 다시 signal을 호출한 프로세스의 수행을 재개한다.
      </li>
      <li>
        중요한 점은 모니터는 조건 변수를 이용하여 아래오 같은 프로세스 실행 순서 제어를 위한 동기화를 제공한다.
      </li>
        <ul>
          <li>
            특정 프로세스가 아직 실행될 조건이 되지 않았을 때에는 <strong>wait를 통해 실행을 중단</strong>한다.
          </li>
          <li>
