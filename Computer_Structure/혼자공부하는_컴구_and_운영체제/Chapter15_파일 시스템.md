<h1>1. 파일과 디렉터리</h1>
<ul>
  <li>
    당연하게 사용해 왔던 파일과 디렉터리는 모두 운영체제 내부 파일 시스템이 관리하는 존재이다.
  </li>
  <li>
    파일과 디렉터리는 <strong>보조기억장치</strong>에 있는 데이터 덩어리일 뿐이며 운영체제가 이를 관리한다.
  </li>
</ul>

<br>

<h2>1-1. 파일</h2>
<ul>
  <li>
    파일(file)이란 하드 디스크나 SSD와 같은 <strong>보조기억장치</strong>에 저장된 <strong>관련 정보의 집합</strong>을 의미한다.
  </li>
    <ul>
      <li>
        모든 파일에는 <strong>속성(attribute)</strong> 또는 <strong>메타데이터(metadata)</strong>가 있다.
      </li>
        <ul>
          <li>
            파일 속성이란 윈도우에서 임의의 파일을 우클릭 한 후 [속성]을 선택하면 나오는 파일 형식, 위치, 크기 등 파일과 관련된 정보들이다.
          </li>
        </ul>
    </ul>
</ul>

<h3>1-1-1. 파일 속성과 유형</h3>
<ul>
  <li>
    운영체제마다 유지하는 파일 속성은 조금씩 차이가 있으며 대표적인 속성의 종류는 p442를 참고.
  </li>
  <li>
    파일 속성 중 파일 유형은 <strong>운영체제가 인식하는 파일 종류</strong>를 나타낸다. 같은 이름의 파일이라도 텍스트 파일, 실행 파일, 음악 파일 등 유형이 다르면 실행 양상도 달라진다.
  </li>
    <ul>
      <li>
        따라서 운영체제에 파일 유형을 알려 주어야 하며 이때 흔히 사용하는 방식은 파일 이름 뒤에 붙는 <strong>확장자(extension)</strong>를 이용하는 것이다. (확장자 종류는 p442 참고).
      </li>
    </ul>
</ul>

<h3>1-1-2. 파일 연산을 위한 시스템 호출</h3>
<ul>
  <li>
    어떤 응용 프로그램도 임의로 파일을 조작할 수 없고 파일을 다루기 위해서는 운영체제에 부탁해야 한다. 이룰 위해 운영체제는 파일 연산을 위한 다음과 같은 <strong>시스템 호출</strong>을 제공한다.
  </li>
    <ul>
      <li>
        파일 생성
      </li>
      <li>
        파일 삭제
      </li>
      <li>
        파일 열기
      </li>
      <li>
        파일 닫기
      </li>
      <li>
        파일 읽기
      </li>
      <li>
        파일 쓰기
      </li>
    </ul>
</ul>

<br>

<h2>1-2. 디렉터리</h2>
<ul>
  <li>
    파일들을 일목요연하게 관리하기 위해 <strong>디렉터리(directory)</strong>를 이용할 수 있으며 윈도우 운영체제에서는 디렉터리를 <strong>폴더(folder)</strong>라고 부른다.
  </li>
  <li>
    과거에는 운영체제에 <strong>하나의 디렉터리</strong>만 존재하였으며 모든 파일은 해당 디렉터리 아래에 존재하였다. 이런 디렉터리 구조를 <strong>1단계 디렉터리(single-level directory)</strong>라고 한다.
  </li>
  <li>
    하지만 용량이 커지고 저장해야할 파일이 많아지면서 여러 계층을 가진 <strong>트리 구조 디렉터리(tree-structured directory)</strong>가 생겨났다.
  </li>
    <ul>
      <li>
        트리 구조 디렉터리는 최상위 디렉터리가 있고 그 아래에 여러 <strong>서브 디렉터리(자식 디렉터리)</strong>가 있을 수 있다.
      </li>
      <li>
        서브 디렉터리는 또 다른 서브 디렉터리를 가질 수 있다.
      </li>
      <li>
        최상위 디렉터리는 흔히 <strong>루트 디렉터리(root directory)</strong>라고 부르고 <strong>슬래시(/)</strong>로 표현한다.
      </li>
      <li>
        이 과정에서 자연스럽게 생긴 개념이 <strong>경로(path)</strong>이다. 경로는 디렉터리를 이용할 파일 위치, 나아가 파일 이름을 특정 짓는 정보이다.
      </li>
    </ul>
</ul>

<h3>1-2-1. 절대 경로와 상대 경로</h3>
<ul>
  <li>
    루트 디렉터리와 파일까지의 경로가 다르면 동일한 이름의 파일이 공존할 수 있다. 따라서 모드 파일은 <strong>루트 디렉터리에서 다기 자신까지 이르는 고유한 경로</strong>를 가지고 있으며 이러한 경로를 <strong>절대 경로(absolute path)</strong>라고 부른다.
  </li>
  <li>
    경로를 나타내는 또 다른 대중적인 방법으로는 <strong>상대 경로(relative path)</strong>가 있다. 절대 경로가 루트 디렉터리부터 시작하는 경로라면 상대 경로는 <strong>현재 디렉터리부터 시작하는 경로</strong>이다.
  </li>
</ul>   

<h3>1-2-2. 디렉터리 연산을 위한 시스템 호출</h3>
<ul>
  <li>
    운영체제는 파일 연산을 위한 시스템 호출 뿐만 아니라 디렉터리 연산을 위한 시스템 호출도 제공한다.
  </li>
    <ul>
      <li>
        디렉터리 생성
      </li>
      <li>
        디렉터리 삭제
      </li>
      <li>
        디렉터리 열기
      </li>
      <li>
        디렉터리 닫기
      </li>
      <li>
        디렉터리 읽기
      </li>
    </ul>
</ul>

<h3>1-2-3. 디렉터리 엔드리</h3>
<ul>
  <li>
    운영체제는 디렉터리를 그저 <strong>특별한 형태의 파일</strong>로 간주한다. 즉 디렉터리도 <strong>파일</strong>이며 조금 특별할 뿐인 것이다.
  </li>
  <li>
    파일이 내부에 해당 파일과 관련된 정보를 담고 있듯이 디렉터리는 내부에 <strong>해당 디렉터리에 담겨 있는 대상과 관련된 정보</strong>를 담고 있다.
  </li>
    <ul>
      <li>
        이 정보는 보통 <strong>테이블(표) 형태</strong>로 구성된다. 즉, 디렉터리는 <strong>보조기억장치에 테이블 형태로 저장</strong>된다.
      </li>
      <li>
        이 때 각 테이블의 <strong>행</strong>을 <strong>엔트리</strong>라고 한다.
      </li>
    </ul>
  <li>
    각각의 엔트리(행)에 담기는 정보는 파일 시스템마다 차이가 있지만, 파일 시스템을 막론하고 디렉터리 엔트리는 <strong>디렉터리에 포함된 대상의 이름</strong>과 그 대상이 <strong>보조기억장치 내에 저장된 위치를 유추</strong>할 수 았는 정보를 포함한다.
  </li>
</ul>

<h4>상대 경로를 나타내는 또 다른 방법</h4>
<ul>
  <li>
    대부분의 운영체제는 혀재 작업 디렉터리를 <strong>마침표(.)</strong>로 나타내고, 현재 작업 디렉터리의 상위 디렉터리(부모 디렉터리)를 <strong>마침표 두 번(..)</strong>으로 나타내며 이 기호를 이용해 상대 경로를 표현한다.
  </li>
  <li>
    윈도우, 리눅스, 유닉스, macOS 등 대부분의 운영체제에서는 <strong>cd(change directory)</strong> 명령을 통해 현재 작업 디렉터리를 이동할 수 있다.
  </li>
</ul>

<br><br>

<h1>2. 파일 시스템</h1>
<ul>
  <li>
    파일 시스템은 파일과 디렉터리를 보조기억장치에 일목요연하게 저장하고 접근할 수 있게 하는 운영체제 내부 프로그램이다.
  </li>
  <li>
    다양한 파일 시스템이 있으며 하나의 컴퓨터에서 여러 파일 시스템을 사용할 수 있다.
  </li>
  <li>
    대표적인 파일 시스템인 <strong>FAT 파일 시스템</strong>과 <strong>유닉스 파일 시스템</strong>을 학습한다.
  </li>
</ul>

<br>

<h2>2-1. 파티셔닝과 포매팅</h2>
<ul>
  <li>
    보조기억장치를 사용하기 위해서는 <strong>파티션을 나누는 작업(파티셔닝)</strong>과 <strong>포맷 작업 (포매팅)</strong>을 거쳐야 한다.
  </li>
  <li>
    <strong>파티셔닝(partitioning)</strong>은 저장 장치의 <strong>논리적인 영역을 구획</strong>하는 작업이다.
  </li>
    <ul>
      <li>
        파티셔닝 작업을 통해 나누어진 영역 하나하나를 <strong>파티션(partition)</strong>이라고 한다.
      </li>
    </ul>
  <li>
    포매팅(formatting)은 파일 시스템을 설정하여 <strong>어떤 방식으로 파일을 저장하고 관리</strong>할 것인지를 결정하고, <strong>새로운 데이터를 쓸 준비</strong>를 하는 작업을 의미한다.
  </li>
    <ul>
      <li>
        즉, <strong>어떤 종류의 파일 시스템</strong>을 사용할지는 이때 결정난다.
      </li>
      <li>
        포매팅에는 저장 장치를 생성할 당시 공장에서 수행되는 물리적 포매팅인 <strong>저수준 포매팅</strong>과 파일 시스템을 생성하는 <strong>논리적 포매팅</strong> 두 가지가 있다. 도서에서 다루는 것은 논리적 포매팅이다.
      </li>
    </ul>
  <li>
    파티션마다 다른 파일 시스템을 설정할 수도 있다.
  </li>
  <li>
    파티셔닝과 포매팅은 동시에 진행되는 경우가 많고 이미 포매팅까지 완료되어 판매되는 경우도 많아 개념에 익숙하지 않을 수 있지만, 저장 장치를 관리하거나 운영체제를 설치하는 과정에서 자주 접하게 될 키워드이기에 기억해 두는 것이 좋다.
  </li>
</ul>

<br>

<h2>2-2. 파일 할당 방법</h2>
<ul>
  <li>
    운영체제는 파일과 디렉터리를 <strong>블록(block) 단위</strong>로 읽고 쓴다.
  </li>
    <ul>
      <li>
        하나의 파일이 보조기억장치에 저장될 때 <strong>하나 이상의 블록</strong>에 걸쳐 저장된다.
      </li>
      <li>
        하드 디스크의 가장 작은 저장 단위는 섹터이지만, 운영체제는 <strong>하나 이상의 섹터를 블록이라는 단위로 묶어</strong> 블록 단위로 파일과 디렉터리를 관리한다.
      </li>
    </ul>
  <li>
    파일을 보조기억장치에 할당하는 방법에는 크게 <strong>연속 할당</strong>과 <strong>불연속 할당</strong> 두 가지가 있다.
  </li>
    <ul>
      <li>
        불연속 할당은 다시 크게 <strong>연결 할당</strong>과 <strong>색인 할당</strong>으로 나뉜다.
      </li>
    </ul>
</ul>

<h3>2-2-1. 연속 할당</h3>
<ul>
  <li>
    <strong>연속 할당(contiguous allocation)</strong>은 가장 단순한 방식으로 보조기억장치 내 <strong>연속적인 블록</strong>에 파일을 할당한다.
  </li>
  <li>
    연속으로 할당된 파일에 접근하기 위해서는 파일의 <strong>첫 번째 블록 주소</strong>와 <strong>블록 단위의 길이</strong>만 알면된다.
  </li>
    <ul>
      <li>
        따라서 디렉터리 엔트리에 파일 이름과 더불어 첫 번째 블록 주소와 블록 단위 길이를 명시한다.
      </li>
    </ul>
  <li>
    연속 할당 방식은 파일을 그저 연속적으로 저장하는 방식이기에 구현이 단순하다는 장점이 있으나 <strong>외부 단편화</strong>를 야기한다는 치명적인 문제가 있다.
  </li>
</ul>

<h3>2-2-2. 연결 할당</h3>
<ul>
  <li>
    <strong>연결 할당(linked allocation)</strong>은 블록 일부에 <strong>다음 블록의 주소를 저장</strong>하여 각 블록이 <strong>다음 블록을 가리키는 형태</strong>로 할당하는 방식이다.
  </li>
    <ul>
      <li>
        파일을 이루는 데이터를 <strong>연결 리스트</strong>로 관리한다.
      </li>
      <li>
        연결 할당은 불연속 할당의 일종이기에 파일이 여러 블록에 <strong>흩어져 저장</strong>되어도 무방하다.
      </li>
      <li>
        어떤 블록의 주소를 저장한다는 말은 <strong>그 블록을 가리킨다</strong>는 말과 같다. 해당 블록의 주소를 알면 얼마든지 접근이 가능하기 때문이다. C언어의 포인터와 같은 개념이다.
      </li> 
    </ul>
  <li>
    연결 할당은 외부 단편화 문제를 해결하지만 이 또한 단점이 존재한다.
  </li>
    <ul>
      <li>
        첫째, 반드시 첫 번째 블록부터 하나씩 차례대로 읽어야 한다.
      </li>
        <ul>
          <li>
            반드시 첫 번째 블록부터 접근하여 하나씩 차례대로 읽어야하기 때문에 파일 내 임의의 위치에 접근하는 속도인 <strong>임의 접근(random access) 속도</strong>가 매우 느리다.
          </li>
        </ul>
      <li>
        둘째, 하드웨어 고장이나 오류 발생 시 해당 블록 이후 블록은 접근할 수 없다.
      </li>
        <ul>
          <li>
            하나의 블록 안에 <strong>파일 데이터</strong>와 <strong>다음 블록 주소</strong>가 모두 포함되어 있어 하드웨어 고장이나 오류로 파일을 이루는 블록이 하나라도 문제가 발생하면 <strong>해당 블록 이후의 블록에 접근할 수 없다</strong>.
          </li>
          <li>
            예를 들어 플래터 위에 대단히 미세한 간격으로 데이터가 존재하기 때문에 헤드가 플래터에 충돌하면 데이터를 손상시킬 수 있다. 따라서 오늘날에는 그대로 구현을 하기보다 조금 변현하여 사용한다.
          </li>
        </ul>
    </ul>
</ul>

<h3>2-2-3. 색인 할당</h3>
<ul>
  <li>
    <strong>색인 할당(indexed allocation)</strong>은 파일의 모든 브록 주소를 <strong>색인 블록(index block)</strong>이라는 <strong>하나의 블록에 모아 관리</strong>하는 방식이다.
  </li>
  <li>
    색인 할당은 연결 할당과 달리 파일 내 임의의 위치에 접근하기 쉽다. 색인을 통해 접근하기 때문이다.
  </li>
  <li>
    색인 블록 안에 파일을 구성하는 데이터 블록 주소가 있기 때문에 색인 할당을 사용하는 파일 시스템에서는 디렉터리 엔트리 파일 이름과 더불어 <strong>색인 블록 주소</strong>를 명시한다.
  </li>
  <li>
    색인 할당을 기반으로 만든 파일 시스템이 유닉스 파일 시스템이다.
  </li>
</ul>

<br>

<h2>2-3. 파일 시스템 살펴보기</h2>
<ul>
  <li>
    여러 전공서에서 공통으로 소개하는 파일 시스템은 크게 두 가지로 하나는 USB 메모리, SD 카드 등의 <strong>저용량 저장 장치</strong>에서 사용되는 <strong>FAT 파일 시스템</strong>이고, 다른 하나는 <strong>유닉스 계열 운영체제</strong>에서 사용되는 <strong>유닉스 파일 시스템</strong>이다.
  </li>
</ul>

<h3>2-3-1. FAT 파일 시스템</h3>
<ul>
  <li>
    연결 할당의 근본적인 문제 중 하나인 <strong>블록 안에 다음 블록의 주소를 저장</strong>한다는 점을 보완한 파일 시스템이 <strong>FAT 파일 시스템</strong>이다.
  </li>
    <ul>
      <li>
        FAT 파일 시스템은 각 블록에 포함된 다음 블록의 주소들을 한데 모아 <strong>테이블 형태로 관리</strong>하며 이러한 테이블을 <strong>파일 할당 테이블(FAT; File Allocation Table)</strong>이라 한다.
      </li>
    </ul>
  <li>
    FAT을 구축한 후에는 디렉터리 엔트리에 <strong>파일 이름</strong>과 더불어 <strong>첫 번째 블록 주소</strong>를 명시하여 FAT에서 찾아서 타고갈 수 있게 한다. (p462).
  </li>
  <li>
    FAT 파일 시스템은 옛 마이크로소프트 운영체제인 MS-DOS에서 사용되었고 최근까지 USB 메모리, SD 카드와 같은 저용량 저장 장치용 파일 시스템으로 많이 이용되고 있다.
  </li>
  <li>
    FAT 파일 시스템은 버전에 따라 FAT12, FAT16, FAT32가 있으며 뒤에 오는 숫자는 블록을 표현하는 <strong>비트 수</strong>를 의미한다.
  </li>
    <ul>
      <li>
        윈도우에서는 블록이라는 용어 대신 클러스터라는 용어를 사용한다.
      </li>
    </ul>
  <li>
    FAT 파일 시스템에서 FAT는 파티션의 앞부분에 만들어진다.
  </li>
    <ul>
      <li>
        예약 영역 - FAT 영역 - 루트 디렉터리 영역 - 데이터 영역
      </li>
    </ul>
  <li>
    FAT는 하드 디스크 파티션의 시작 부분에 있지만, 실행하는 도중 <strong>메모리에 캐시</strong>될 수 있다.
  </li>
    <ul>
      <li>
        FAT가 메모리에 적재된 채 실행되면 기존 연결 할당보다 다음 블록을 찾는 속도가 매우 빨라지고, 결과적으로 <strong>임의 접근에도 유리</strong>해진다.
      </li>
    </ul>
  <li>
    FAT 파일 시스템의 디렉터리 엔트리에는 <strong>파일 속성과 관련된 다양한 정보</strong>들이 존재한다.
  </li>
    <ul>
      <li>
        파일 이름, 확장자, 속성, 예약 영역, 생성 시간, 마지막 접근 시간, 마지막 수정 시간, 시작 블록, 파일 크기
      </li>
      <li>
        속성(File Attribute) 항목은 해당 파일이 읽기 전용인지, 숨김 파일인지, 시스템 파일인지, 일반 파일인지, 디렉터리인지 등을 시별하기 위한 항목이다.
      </li>
    </ul>
  <li>
    어떻게 진행되는지는 p465 참고.
  </li>
</ul>

<h3>2-3-2. 유닉스 파일 시스템</h3>
<ul>
  <li>
    유닉스 파일 시스템에서는 색인 블록을 <strong>i-node(index-node)</strong>라고 부른다.
  </li>
    <ul>
      <li>
        i-node에는 파일 속성 정보와 열다섯 개의 블록 추소가 저장될 수 있다.
      </li>
      <li>
        FAT 파일 시스템에서는 파일 속성 정보가 디렉터리 엔트리에 표현되는 반면 유닉스 파일 시스템은 파일 시스템에서 파일 속성 정보는 i-node에 표현된다.
      </li>
    </ul>
  <li>
    유닉스 파일 시스템에는 파일마다 i-node가 있고, i-node마다 번호가 부여되어 있다.
  </li>
    <ul>
      <li>
        i-node들은 파이션 내 특정 영역에 모여있다.
      </li>
        <ul>
          <li>
            i-node 영역에는 i-node들이, 데이터 영역에는 디렉터리와 파일들이 있다.
          </li>
        </ul>
    </ul>
  <li>
    i-node는 15개의 블록 주소를 저장할 수 있기 때문에 20개, 30개 등 15개의 블록 이상의 파일을 모두 처리할 수는 없으며 이러한 문제를 다음의 방법들로 처리한다.
  </li>
    <ul>
      <li>
        첫째, 블록 주소 중 열두 개에는 <strong>직접 블록 주소</strong>를 저장한다.
      </li>
        <ul>
          <li>
            i-node가 가리킬 수 있는 열다섯 개의 블록 주소 중 처음 열두 개에 파일 데이터를 저장한다. 이것만으로 파일 데이터 블록을 모두 가리킬 수 있다면 추가 작업은 필요하지 않다.
          </li>
          <li>
            파일 데이터가 저장된 블록을 <strong>직접 블록(direct block)</strong>이라고 한다.
          </li>
          <li>
            포인터는 여럿 가질 수 있다.
          </li>
        </ul>
      <li>
        둘때, '첫째' 내용으로 충분하지 않다면 열세 번째 주소에 <strong>단일 간접 블록 주소</strong>를 저장한다.
      </li>
        <ul>
          <li>
            <strong>단일 간접 블록(single indirect block)</strong>이란 파일 데이터가 저장된 블록이 아니라 파일 데이터를 저장한 <strong>블록 주소</strong>가 저장된 블록을 의미한다.
          </li>
          <li>
            따라서 단일 간접 블록에서 <strong>한 번 더 블록 주소를 찾아</strong> 파일 데이터를 찾아간다.
          </li>
        </ul>
      <li>
        셋째, '둘째' 내용으로 충분하지 않다면 열네 번째 주소에 <strong>이중 간접 블록 주소</strong>를 저장한다.
      </li>
        <ul>
          <li>
            열세 개의 블록으로도 부족하다면 열네 번째 블록 주소에 <strong>이중 간접 블록(double indirect block) 주소</strong>를 저장한다.
          </li>
          <li>
            즉 한 번 더 블록 데이터의 주소를 저장하기 때문에 <strong>두 번 주소를 찾은 후</strong>에 데이터에 접근한다.
          </li>
        </ul>
      <li>
        넷째, '셋째' 내용으로 충분하지 않다면 열다섯 번째 주소에 <strong>삼중 간접 블록 주소</strong>를 저장한다.
      </li>
        <ul>
          <li>
            열네 개의 블록으로도 부족하다면 i-node의 열다섯 번째 블록 주소에 <strong>삼중 간접 블록(triple indirect block)</strong>을 두어 활용한다.
          </li>
          <li>
            말 그대로 블록 주소를 이전과 같이 중첩하여 세 번 중첩한 구조이며 <strong>주소를 세 번 찾은 후</strong> 데이터에 접근한다.
          </li>
        </ul>
    </ul>
  <li>
    윈도우 운영체제에서는 NT 파일 시스템(NTFS)을, 리눅스 운영체제에서는 ext 파일 시스템 등이 있다. 
  </li>
</ul>

<h4>저널링 파일 시스템</h4>
<ul>
  <li>
    파일 시스템을 변경하는 도중 갑자기 전원이 나가거나 치명적인 오류로 컴퓨터가 간제로 종료되어 버린다면(시스템 크래시) 파일 시스템이 훼손될 수 있다.
  </li>
  <li>
    저널링 파일 시스템은 저널링(journaling) 기법으로 시스템 크래시가 발생했을 때 <strong>작업 로그</strong>를 통해 빠르게 복구를하는 방법이며 다음과 같은 순서로 수행된다.
  </li>
    <ol>
      <li>
        작업 직전 파티션의 로그 영역에 수행하는 작업(변경 사항)에 대한 로그를 남긴다.
      </li>
      <li>
        로그를 남긴 후 작업을 수행한다.
      </li>
      <li>
        작업이 끝났다면 로그를 삭제한다.
      </li>
    </ol>
  <li>
    결과적으로 작업을 하던 도중 시스템 크래시가 발생하여 다시 부팅을 해도 시스템 전체를 검사할 필요 없이 <strong>로그 영역에 남김 로그</strong>만 검사해도 된다.
  </li>
  <li>
    마이크로소프트의 NT 파일 시스템, 리눅스의 ext3, ext4 파일 시스템을 포함하여 현대 대부분의 파일 시스템은 이러한 저널링 기능을 지원한다.
  </li>
</ul>

<h4>마운트(p476)</h4>
<ul>
  <li>
    마운트란 한 저장 장치의 파일 시스템에서 다른 저장 장치의 파일 시스템에 접근할 수 있도록 파일 시스템을 편입 시키는 작업을 의미한다.
  </li>
  <li>
    유닉스, 리눅스와 같은 운영체제에 다양한 저장 장치를 컴퓨터에 연결할 때 mount 명령어로 빈번하게 마운트를 한다.
  </li>
</ul>
