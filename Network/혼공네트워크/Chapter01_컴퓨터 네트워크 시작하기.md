<h1>1. 컴퓨터 네트워크를 알아야 하는 이유</h1>
<ul>
  <li>
    여러 개의 장치가 마치 그물처럼 서로 연결되어 정보를 주고받을 수 있는 통신망을 컴퓨터 네트워크(computer network)라 한다.
  </li>
</ul>

<br>

<h2>1-1. 네트워크의 네트워크, 인터넷</h2>
<ul>
  <li>
    인터넷(internet)이란 여러 네트워크를 연결한 네트워크의 네트워크이다.
  </li>
    <ul>
      <li>
        여러 장치들이 네트워크에 연결되면 주변 장치 뿐만아니라 네트워크와 연결된 곳이라면 어디든 정보를 주고 받을 수 있다.
      </li>
    </ul>
  <li>
    개발에 있어서도 네트워크를 이용하는 프로그램, 즉 다른 장치와 상호 작용하며 실행되는 프로그램을 개발하는 경우가 많으며 따라서 네트워크에 대해 이해해 두는 것이 좋다.
  </li>
</ul>

<br>

<h2>1-2. 개발자가 컴퓨터 네트워크를 알아야 하는 이유</h2>
<ul>
  <li>
    도서에서는 개발자의 업무를 크게 다음 두 가지로 나눈다. 그리고 네트워크는 두 가지 업무에 모두 도움을 준다.
  </li>
    <ul>
      <li>
        프로그램을 만드는 업무
      </li>
      <li>
        만들어진 프로그램을 유지 보수하는 업무
      </li>
    </ul>
</ul>

<h3>1-2-1. 프로그램을 만드는 업무에서 네트워크 지식을 활용하는 경우</h3>
<ul>
  <li>
    TCP/UDP와 같은 네트워크의 지식, HTTP와 쿠키, DNS, HTTP/HTTPs, 포트 등 다양한 네트워크 지식들을 알고 있는 것이 도움이 된다.
  </li>
</ul>

<h3>1-2-2. 프로그램을 유지 보수하는 업무에서 네트워크 지식을 활용하는 경우</h3>
<ul>
  <li>
    갑자기 인터넷 연결이 안되는 경우, 웹 서버가 갑자기 죽은 경우, 프로그램 유지 보수 등의 경우에서 유용하게 활용할 수 있다.
  </li>
</ul>

<br><br>

<h1>2. 네트워크 거시적으로 살펴보기</h1>
<ul>
  <li>
    네트워크는 여러 장치가 서로 연결되어 정보를 주고 받을 수 있는 통신망이며 모양은 <strong>그래프(graph) 형태</strong>를 띠고 있다.
  </li>
    <ul>
      <li>
        그래프란 <strong>노드(node)</strong>와 노드를 연결하는 <strong>간선(edge)</strong>으로 이루어진 자료 구조이다.
      </li>
    </ul>
</ul>

<br>

<h2>2-1. 네트워크의 기본 구조</h2>
<ul>
  <li>
    모든 네트워크는 <strong>노드</strong>, 노스를 연결하는 <strong>간선</strong>, 노드 간 주고받는 <strong>메시지</strong>로 구성된다.
  </li>
    <ul>
      <li>
        간선은 정보를 주고받을 수 있는 유무선의 통신 매체라 이해하면 쉽다.
      </li>
    </ul>
</ul>

<h3>2-1-1. 호스트</h3>
<ul>
  <li>
    네트워크의 <strong>가장자리에 위치한 노드</strong>는 네트워크를 흐르는 정보를 최초로 생성 및 송신하고, 최종적으로 수진하는데 이러한 가장자리 노드를 네트워크에서는 <strong>호스트(host)</strong>라고 한다.
  </li>
    <ul>
      <li>
        호스트는 네트워크의 가장자리에 자리 잡고 있다는 점에서 <strong>종단 시스템(end system)</strong>이라고도 한다.
      </li>
    </ul>
  <li>
    때로는 호스트가 네트워크에서 특정한 역할을 수행하기도 하는데, 대표적으로 <strong>서버(server)</strong>와 <strong>클라이언트(client)</strong>가 이다.
  </li>
    <ul>
      <li>
        <strong>서버(server)</strong>는 어떠한 서비스를 제공하는 호스트이다.
      </li>
        <ul>
          <li>
            서버는 파일(파일 서버), 웹 페이지(웹 서버), 메일(메일 서버) 등 다양한 서버가 될 수 있다.
          </li>
          <li>
            서버라는 용어는 serve에서 비롯되었다.
          </li>
        </ul>
      <li>
        <strong>클라이언트(client)</strong>란 서버에 어떠한 요청을 서비스를 요청하고 서버의 응답을 제공받는 호스트이다.
      </li>
        <ul>
          <li>
            클라이언트는 서버에 <strong>요청(request)</strong>을 보내고 그에 대한 <strong>응답(response)</strong>을 제공받는다.
          </li>
        </ul>
    </ul>
</ul>

<h3>2-1-2. 네트워크 장비</h3>
<ul>
  <li>
    네트워크 노드에는 호스트 외에도 호스트간 주고받을 정보가 중간에 거치는 노드들도 있으며 이런 노드들을 <strong>중간 노드</strong>라 한다.
  </li>
    <ul>
      <li>
        대표적으로는 앞으로 학습할 허브, 스위치, 라우터, 공유기 등이 있다.
      </li>
      <li>
        도서에서는 이러한 중간 노드들을 <strong>네트워크 장비</strong>라 통칭한다.
      </li>
      <li>
        네트워크 장비는 호스트 간 주고받는 정보가 원하는 수신지까지 안정적이고 안전하게 전송될 수 있도록 한다.
      </li>
    </ul>
</ul>

<h4>호스트, 네트워크 장비, 서버, 클라이언트는 완전히 배타적인 개념일까요?</h4>
<ul>
  <li>
    네트워크 노드의 분류는 역할에 따라 분류를 한 것일뿐이다.
  </li>
  <li>
    따라서 호스트와 네트워크 장비로 나뉠 수 있지만 이 둘 모두를 수행할 수도 있다.
  </li>
  <li>
    서버와 클라이언트 또한 역할에 따른 구분일 뿐 둘 모두의 역할을 수행할 수 있다.
  </li>
  <li>
    핵심은 다음 두 가지이다.
  </li>
    <ul>
      <li>
        호스트 역할을 수행할 수 있는 노드, 네트워크 장비 역할을 수행할 수 있는 노드가 있다.
      </li>
      <li>
        서버 역할을 수행할 수 있는 노드, 클라이언트 역할을 수행할 수 있는 노드가 있다.
      </li>
    </ul>
</ul>

<h3>2-1-3. 통신 매체</h3>
<ul>
  <li>
    그래프는 노드, 그리고 노드를 연결 짓는 간선(링크)으로 이루어지기 때문에 호스트와 네트워크 장비 또한 <strong>유무선 매체</strong>를 통해 <strong>연결</strong>되어 있어야 한다.
  </li>
  <li>
    각 노드를 연결하는 간선을 <strong>통신 매체</strong>라 한다.
  </li>
    <ul>
      <li>
        통신 매체에는 노드들을 유선으로 연결하는 <strong>유선 매체</strong>, 무선으로 연결하는 <strong>무선 매체</strong>가 있다.
      </li>
    </ul>
</ul>

<h3>2-1-4. 메시지</h3>
<ul>
  <li>
    통신 매체로 연결된 노드가 주고받는 정보를 <strong>메시지(message)</strong>라고 한다.
  </li>
    <ul>
      <li>
        메시지는 웹 페이지, 파일, 메일 등 다양한 형태일 수 있다.
      </li>
    </ul>
  <li>
    정리를 하면 네트워크는 다음의 구성으로 이루어진다.
  </li>
    <ul>
      <li>
        가장자리 노드인 호스트
      </li>
      <li>
        중간 노드인 네트워크 장비
      </li>
      <li>
        노드들을 연결하는 간선인 통신 매체
      </li>
      <li>
        노드들이 주고받는 정보인 메시지
      </li>
    </ul>
</ul>

<br>

<h2>2-2. 범위에 따른 네트워크 분류</h2>
<ul>
  <li>
    호스트가 메시지를 주고받는 범위는 일반 가정이 될 수도 있고, 기업, 때로는 도시나 국가 등 <strong>네트워크 구성 범위는 다양</strong>하다.
  </li>
  <li>
    네트워크는 범위에 따라 크게 <strong>LAN</strong>과 <strong>WAN</strong>으로 구분한다.
  </li>
</ul>

<h3>2-2-1. LAN</h3>
<ul>
  <li>
    <strong>LAN</strong>은 <strong>Local Area Network의 약자</strong>로 이름 그대로 <strong>가까운 지역</strong>을 연결한 근거리 통신망을 의미한다.
  </li>
    <ul>
      <li>
        가정, 기업, 학교 등 한정된 공간에서의 네트워크가 해당한다.
      </li>
    </ul>
</ul>

<h3>2-2-2. WAN</h3>
<ul>
  <li>
    <strong>WAN</strong>은 <strong>Wide Area Network의 약자</strong>로 <strong>먼 지역을 연결</strong>하는 광역 통신망을 의미한다.
  </li>
  <li>
    멀리 떨어진 LAN을 연결할 수 있는 네트워크가 WAN이다.
  </li>
    <ul>
      <li>
        LAN을 연결하는 것은 네트워크끼리의 연결을 의미하기에 WAN은 네트워크의 네트워크이다. 따라서 <strong>인터넷은 WAN으로 분류</strong>된다.
      </li>
      <li>
        즉 같은 LAN에 속한 호스트끼리 메시지를 주고받을 때는 인터넷 연결과 같은 WAN이 필요 없지만, 다른 LAN에 속한 호스트와 메시지를 주고받기 위해서는 WAN이 필요하다.
      </li>
    </ul>
  <li>
    우리가 인터넷을 사용하기 위해 접속하는 WAN은 <strong>ISP(Internet Service Provider)</strong>라는 인터넷 서비스 업체가 구축하고 관리한다.
  </li> 
    <ul>
      <li>
        ISP는 사용자에게 인터넷과 같은 WAN에 연결 가능한 회선을 임대하는 등 WAN과 관련된 다양한 서비스를 제공한다.
      </li>
      <li>
        인터넷을 사용하기 위해 ISP와 계약하여 인터넷 사용 요금을 지불하는 이유도 위와 같은 이유 때문이다.
      </li>
    </ul>
  <li>
    인터넷이 WAN의 전부는 아니며 멀리 떨어진 LAN을 연결하기 위해 특정 조직에서 불특정 다수에게 공개되지 않은 WAN을 구축할 수도 있다.
  </li>
</ul>

<h4>CAN과 MAN</h4>
<ul>
  <li>
    LAN과 WAN을 더 세밀하게 나누면 LAN보다는 넓고 WAN보다는 좁은 대표적인 네트워크로 CAN과 MAN이 있다.
  </li>
  <li>
    <strong>CAN(Campus Area Network)</strong>은 학교 또는 회사의 여러 건물 단위로 연결되는 규모의 네트워크를 의미한다.
  </li>
  <li>
    <strong>MAN(Metropolitan Area Network)</strong>은 도시나 대도시 단위로 연결되는 규모의 네트워크를 의미한다.
  </li>
  <li>
    정리를 하면 <strong>WAN > MAN > CAN > LAN</strong>순으로 작아진다고 볼 수 있다.
  </li>
</ul>

<br>

<h2>2-3. 메시지 교환 방식에 따른 네트워크 분류</h2>
<ul>
  <li>
    네트워크로 메시지를 주고받는 방식은 대표적으로 <strong>회선 교환 방식</strong>과 <strong>패킷 교환 방식</strong>으로 나눌 수 있다.
  </li>
    <ul>
      <li>
        각 방식을 사용하는 네트워크를 각각 <strong>회선 교환 네트워크</strong>와 <strong>패킷 교환 네트워크</strong>라고 한다.
      </li>
    </ul>
</ul>

<h3>2-3-1. 회선 교환 방식</h3>
<ul>
  <li>
    <strong>회선 교환(circuit switching)</strong> 방식은 먼저 메시지 전송로인 <strong>회선(circuit)</strong>을 설정하고 이를 통해 메시지를 주고받는 방식이다.
  </li>
    <ul>
      <li>
        회선을 설정한다는 의미는 두 호스트가 연결되었다 혹은 전송로를 확보하였다 라는 의미와 같다.
      </li>
    </ul>
  <li>
    회선 교환 방식은 우선 두 호스트 사이에 연결을 확보한 후에 메시지를 주고받는 특성 덕에 <strong>주어진 시간 동안 전송되는 정보의 양이 비교적 일정</strong>하다는 장점이 있다.
  </li>
    회선 교환 네트워크가 올바르게 작동하기 위해서는 <strong>호스트 간의 회선을 적절하게 설정</strong>해야 한다. 이 역할을 수행하는 회선 교환 네트워크 장비로 <strong>회선 스위치</strong>가 있다.
  </li>
    <ul>
      <li>
        회선 스위치는 <strong>호스트 사이에 일대일 전송로</strong>를 확보하는 네트워크 장비이다.
      </li>
    </ul>
  <li>
    회선 교환 방식의 대표적인 사례는 <strong>전통적인 전화망</strong>이다. 전화망은 누군가에게 전화를 걸면 수신자가 전화를 받기 전에 <strong>송신자와 수신자 사이에 연결</strong>이 설정된다.
  </li>
    <ul>
      <li>
        한 번 연결이 설정되면 <strong>연결된 전송로를 통해서만 통화</strong>가 가능하다.
      </li>
    </ul>
  <li>
    회선 교환 방식에는 <strong>회선의 이용 효율</strong>이 낮아질 수 있다는 문제점이 있다.
  </li>
    <ul>
      <li>
        효율을 높이기 위해서는 가능한 모든 회선에 끊임없이 메시지가 흐르고 있어야만 한다.
      </li>
      <li>
        반대로 메시지를 주고받지 않으면서 회선을 점유하는 것은 시간 낭비로 볼 수 있다.
      </li>
      <li>
        또한 해당 회선을 이용해야하는 노드들도 통신이 불가능하다는 문제가 있다.
      </li>
    </ul>
</ul>

<h3>2-3-2. 패킷 교환 방식</h3>
<ul>
  <li>
    <strong>패킷 교환(packet switching) 방식</strong>은 회선 교환 방식의 문제점을 해결한 방식으로, 메시지를 <strong>패킷</strong>이라는 작은 단위로 쪼개어 전송한다.
  </li>
    <ul>
      <li>
        패킷(packet)은 패킷 교환 네트워크상에서 송수신되는 <strong>메시지의 단위</strong>이다. 현대 인터넷은 대부분 패킷 교환 방식을 이용한다.
      </li>
      <li>
        예를 들어 2GB 크기의 영화 파일을 다운로드한다면 2GB영화는 <strong>작은 패킷 단위로 전송</strong>되어 사용자의 컴퓨터에 도달한 뒤 <strong>재조립</strong>된다.
      </li>
    </ul>
  <li>
    패킷 교환 네트워크는 회선 교환 네트워크와 달리 메시지를 송수신하는 두 호스트가 하나의 전송 경로를 <strong>점유하지 않기 때문</strong>에 네트워크 이용 효율이 상대적으로 높다.
  </li>
  <li>
    패킷이 패킷 교환 네트워크를 통해 먼 곳까지 이동하는 경우 패킷 교환 방식은 정해진 경로만 메시지를 송수진하지 않고 <strong>다양한 중간 노드</strong>를 거칠 수 있다.
  </li>
    <ul>
      <li>
        중간 노드인 패킷 스위치는 패킷이 수신지까지 올바르게 도달할 수 있도록 <strong>최적의 경로를 결정</strong>하거나 <strong>패킷의 송수신지를 식별</strong>한다.
      </li>
    </ul>
  <li>
    대표적인 패킷 스위치 네트워크 장비로 <strong>라우터(router)</strong>와 <strong>스위치(switch)</strong>가 있다.
  </li>
  <li>
    패킷을 통해 전송하고자 하는 데이터를 <strong>페이로드(payload)</strong>라고 한다.
  </li>
    <ul>
      <li>
        페이로드에 더해 <strong>헤더(header)</strong>라는 정보가 <strong>패킷 앞</strong>에 포함된다.
      </li>
      <li>
        때로는 <strong>패킷 뒤</strong>에 <strong>트레일러(trailer)</strong>라는 정보가 포함되기도 한다.
      </li>
      <li>
        헤더와 트레일러는 해킷에 붙는 일종의 부가 정보 혹은 제어 정보이다. 즉 페이로드가 택배 안에 담을 물품이라면 헤더나 트레일러는 택배 상자에 붙이는 송장과 같다.
      </li>
    </ul>
</ul>

<h4>주소와 송수신지 유형에 따른 전송 방식</h4>
<ul>
  <li>
    패킷의 헤더에 담기는 대표적인 정보로는 <strong>주소(address)</strong>가 있다.
  </li>
    <ul>
      <li>
        주소는 송수신지를 특정하는 정보를 의미한다.
      </li>
      <li>
        모든 패킷에는 모두 송수신지가 있으며 <strong>IP주소</strong> 혹은 <strong>MAC 주소</strong>가 해당된다.
      </li>
    </ul>
  <li>
    송수신지를 특정할 수 있는 주소가 있다면 송수신지 유형에 따라 다양한 방식으로 메시지를 보낼 수 있다. 예를 들어 특정 호스트 하나, 네트워크 내 모든 호스트, 자신과 동일한 그룹에 속한 호스트 등이다.
  </li>
  <li>
    송수신지 유형별 전송 방식은 다양한 종류가 있지만, 네트워크의 기본 동작을 파악하기 위해서 알아야 할 가장 중요한 전송 방식은 <strong>유니캐스트</strong>와 <strong>브로드캐스트</strong>이다.
  </li>
    <ul>
      <li>
        <strong>유니캐스트(unicast)</strong>는 가장 일반적인 형태의 송수신 방식으로, <strong>하나의 수신지</strong>에 메시지를 전송하는 방식이다.
      </li>
        <ul>
          <li>
            송신지와 수신지가 <strong>일대일</strong>로 메시지를 주고받는다.
          </li>
        </ul>
      <li>
        <strong>브로드캐스트(broadcast)</strong>는 <strong>자신을 제외한 네트워크상의 모든 호스트</strong>에게 전송하는 방식이다.
      </li>
        <ul>
          <li>
            브로드캐스트가 전송되는 범위를 <strong>브로드캐스트 도메인(broadcast domain)</strong>이라고 한다.
          </li>
          <li>
            브로드캐스트의 수신지는 브로드캐스트 도메인이며 이는 자신을 제외한 네트워크상의 모든 호스트이다.
          </li>
        </ul>
    </ul>
  <li>
    이외로도 네트워크 내의 동일 그룹에 속한 호스트에게만 전송하는 <strong>멀티캐스트(multicast)</strong>, 네트워크 내의 동일 그룹에 속한 호스트 중 가장 가까운 호스트에게 전송하는 <strong>애니캐스트(anycast)</strong> 등 다양한 방식이 있다.
  </li>
</ul>

<h1>3. 네트워크 미시적으로 살펴보기</h1>
<ul>
  <li>
    <strong>프로토콜</strong>은 통신 과정에서 정보를 올바르게 주고받기 위해 합의된 <strong>규칙이나 방법</strong>이다.
  </li>
  <li>
    <strong>네트워크 참조 모델</strong>은 통신이 일어나는 구조를 <strong>계층화</strong> 한 것이다.
  </li>
  <li>
    <strong>캡슐화(역캡슐화)</strong>는 통신 과정에서 이루어지는 작업이다.
  </li>
</ul>

<br>

<h2>3-1. 프로토콜</h2>
<ul>
  <li>
    현대 인터넷은 호스트 간 패킷을 교환하는 방식으로 대부분 <strong>패킷 교환 방식</strong>을 사용한다.
  </li>
  <li>
    택배를 가정해도 택배 송장의 언어는 택배 기사가 이해할 수 있어야 한다. 이와 동일하게 <strong>프로토콜(protocol)</strong>은 노드 간에 정보를 올바르게 주고받기 위해 합의된 규칙이나 방법을 의미한다.
  </li>
    <ul>
      <li>
        서로 다른 통신 장치들이 정보를 주고받으려면 프로토콜을 통해야 한다.
      </li>
      <li>
        통신 과정에서는 하나의 프로토콜만 사용하지 않는다. 일반적으로 여러 프로토콜을 함께 사용한다.
      </li>
    </ul>
  <li>
    예를 들면 다음과 같다.
  </li>
    <ul>
      <li>
        IP는 패킷을 수신지까지 전달하기 위해 사용되는 프로토콜이다.
      </li>
        <ul>
          <li>
            IP: 프로토콜
          </li>
        </ul>
      <li>
        ARP는 192.168.1.1과 같은 형태의 'IP 주소'를 A1:B2:C3:D4:E5:F6과 같은 형태의 'MAC 주소'로 대응하기 위해 사용되는 프로토콜이다.
      </li>
        <ul>
          <li>
            ARP: 프로토콜
          </li>
        </ul>
      <li>
        HTTPS는 HTTP에 비해 보안상 더 안전한 프로토콜이다.
      </li>
        <ul>
          <li>
            HTTP & HTTPS: 프로토콜
          </li>
        </ul>
      <li>
        TCP는 UDP에 비해 일반적으로 느리지만 신뢰성이 높은 프로토콜이다.
      </li>
        <ul>
          <li>
            TCP & UDP: 프로토콜
          </li>
        </ul>
    </ul>
  <li>
    프로토콜의 공통점은 저마다의 <strong>목적</strong>과 <strong>특징</strong>이 있다는 것이다.
  </li> 
    <ul>
      <li>
        프로토콜마다 목적과 특징이 다르기 때문에 이에 부합하는 정보도 달라질 수 있으며 따라서 프로토콜마다 <strong>패킷의 헤더 내용</strong>이 달라질 수 있다. (헤더가 없는 프로토콜도 있다.)
      </li>
    </ul>
</ul>

<br>

<h2>3-2. 네트워크 참조 모델</h2>
<ul>
  <li>
    네트워크를 통해 정보를 주고 받을 때에는 정형화된 여러 단계를 거치며 이 과정은 <strong>계층</strong>으로 표현할 수도 있다.
  </li>
    <ul>
      <li>
        통신이 일어나는 각 과정을 계층으로 나눈 구조를 <strong>네트워크 참조 모델(network reference model)</strong>이라고 한다. 계층으로 표현한다는 점에서 <strong>네트워크 계층 모델</strong>이라 부르기도 한다.
      </li>
    </ul>
  <li>
    통신 과정을 계층으로 나눈 이유는 크게 두 가지이다.
  </li>
    <ul>
      <li>
        <strong>첫째, 네트워크 구성과 설계가 용이하다.</strong>
      </li>
        <ul>
          <li>
            각 계층이 수행해야 할 역할이 정해져 있어 계층의 목적에 맞게 프로토콜과 네트워크 장비를 <strong>계층별로 구성</strong>할 수 있다.
          </li>
          <li>
            물론 항상 계층이 명확하게 구분되지 않을 수도 있다. 특히 네트워크 장비는 상위 게층의 장비가 하위 계층의 장비 역할도 포괄하는 경우도 있지만, 그럼에도 네트워크 참조 모델은 좋은 가이드라인 역할을 수행한다.
          </li>
        </ul>
      <li>
        <strong>둘째, 네트워크 문제 진단과 해결이 용이하다.</strong>
      </li>
        <ul>
          <li>
            통신 과정에서 문제가 발생하더라도 문제의 원인을 <strong>계층별로 진단</strong>하기 수월하다.
          </li>
        </ul>
    </ul>
</ul>
